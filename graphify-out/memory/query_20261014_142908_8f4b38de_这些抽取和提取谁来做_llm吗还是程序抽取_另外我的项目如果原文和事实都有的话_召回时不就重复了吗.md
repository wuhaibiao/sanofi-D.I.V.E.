语义事实抽取主要由LLM完成；程序执行原文保存、JSON/字段规范化、精确去重、索引与查询。你的系统一次待处理批次调用extract LLM产生事实，程序还从助手的编号列表、短动作和表格中做确定性的字面结构回补，明确覆盖时不新增重复结构。检索当前使用程序、Qdrant、Embedding和BGE重排，聊天LLM负责最终回答。Embedding/BGE是模型计算，但不等于聊天LLM事实抽取。

Mem0 OSS默认infer=True的事实提炼调用LLM；实体识别在当前实现还有spaCy等NLP辅助，程序维护存储、去重和检索。infer=False可以直接存输入。Sources: https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py ; https://github.com/mem0ai/mem0/blob/main/mem0/utils/entity_extraction.py
Graphiti常规episode写入中的实体和关系抽取调用LLM；程序/数据库执行节点边持久化、索引和其余图操作，部分语义解析/消歧也可能用LLM。Sources: https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/node_operations.py ; https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/edge_operations.py
Letta Code长期记忆通常由Agent的LLM或后台记忆Agent整理和编辑，通过文件工具写入；SDK也允许直接设置记忆，并非每条消息都固定做一次自动事实抽取。Source: https://docs.letta.com/agent-sdk/memory

你的担心需要区分原文+事实重复、同一事实多通道命中、事实内部语义重叠。实时配置recall_mode=facts、include_sources=False。read.py只对kind=fact发起搜索，store.py在Qdrant查询过滤器里加入tenant/kind/status/revision条件，发生在top-k返回之前；需要全部候选时也只枚举facts，不扩展episode来源。原文留存、即使有索引，也不占逻辑上的事实候选名额；仍占磁盘/物理索引资源。上轮原文摘录和待处理原文均为0。

稠密和词法通道命中的同一Fact按F_ID融合为一条候选。不同ID却语义重叠的模型事实与字面结构、重复描述仍可能占候选和上下文；现有严格覆盖与完全字段去重只处理可证明一致的情况，不保证语义去重。相同value的上下文共享只省展示字节，不删除候选或减少BGE计算。底层旧索引版本也可能占初始ANN命中量，代码检查当前记录、去重并有限扩大抓取，不能因此声称近似检索完整。当前瓶颈需区分事实内部重复和冗长助手建议，不能归因于原文混入事实召回。
