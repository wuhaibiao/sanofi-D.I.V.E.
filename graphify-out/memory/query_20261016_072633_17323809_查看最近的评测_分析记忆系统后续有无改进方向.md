**这些分数都应作为开发回归。** 后续审计确认32题中30题曾在更早记录中出现；Oracle提供限定历史，回答与评分也使用同名模型。因此，目前无法据此证明泛化水平，或把提升全部归因于关系索引。[审计结论](/Users/OleniusBlanc227/Documents/sanofi/memsys/runs/system-handbook-audit-20261014/findings.json:4)

建议按以下优先级改进：

1. **P0：解决长抽取的完整性。** 当前整批抽取，遇到输出截断直接失败；已经有原消息保留和整理水位保护，但仍会阻断记忆形成。先在“正常每批一次抽取”的约束下压缩输出协议：实体、来源统一定义后引用，程序补齐可推导字段，减少重复描述，并保证失败任务可恢复。仅提高输出上限无法解决持续增长的会话。[当前抽取实现](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/write.py:412)

2. **P1：把事实呈现做得更紧凑。** 既有审计显示，原24题成功回答的23题中，15题的事实上下文比原始历史消息正文更长，13题装入了库中全部事实；这是UTF-8字节比较，包含事实元数据。V7相对V6的回答输入token增加26.1%，抽取输出增加128%。优先减少事实句子、value、关系和时间元数据的重复表示，保留数字、条件、来源与顺序。这里同时存在写入和读取两端的优化空间。[上下文审计](/Users/OleniusBlanc227/Documents/sanofi/memsys/runs/system-handbook-audit-20261014/findings.json:18)

3. **P1：完善“当前状态”的表达。** 当前写入主要是追加事实和精确去重，不会普遍建立新旧事实的有效替代关系；版本链读取代码的存在，并不代表正常写入已生成这些链。可以保留追加历史，同时建立可追溯的当前状态视图，优先处理有明确依据的更正，并按实体、属性和条件区分作用范围；模糊冲突继续并存。[写入逻辑](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/update.py:30)

4. **P1：减少不必要的重排推理。** 单题重放中，缓存优化只让热重排缩短约1.4%，模型推理占热重排耗时约99.8%；两题跨会话重放没有显示提速。更值得评估的是：候选事实全部能装入预算、无需筛选时，能否走免重排路径。即使候选相同，顺序仍可能影响回答，需要用自编场景验证。[重排分阶段耗时](/Users/OleniusBlanc227/Documents/sanofi/memsys/runs/rerank-single-question-20261014/summary.json)

5. **P2：细化检索覆盖与关系收益。** 32题中关系扩展仅在3题新增候选，另有6题最终仍标记汇总覆盖不足。下一步应区分“未抽到、未召回、预算未装下、已提供但回答未使用”，并记录关系扩展事实是否进入最终上下文。当前覆盖补取主要是扩大预算、重新装载已有候选，尚不能证明补齐了缺失语义。[覆盖补取实现](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/core.py:245)

实施时可用自编场景检查完整性、状态变更和覆盖，分别记录写入成功率、上下文token及端到端延迟；旧24/32题保留为回归，不依据参考答案补规则。本次未修改生产代码或启动新评测。
