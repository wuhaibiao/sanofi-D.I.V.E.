# Q: 面试官问你的记忆系统和一些开源的有什么区别，有做过相关调研吗；评测集是通用还是领域，和开源项目相比怎么样；了解哪些评测相关系统设计

## Answer

Expanded via existing graph vocabulary: memory eval judge provenance replay runner trace gold. The graph is stale and was used for navigation; current architecture, benchmark loaders, judge, provenance, stage-isolation docs and historical evaluation scope were verified. The project has explicit Mem0 architecture references and historical ConvoMem/LoCoMo research files plus independent24 adaptation design. It is valid to describe architectural research and borrowing, not a completed same-condition OSS victory. Current official sources: Mem0 is a general memory layer and now documents hybrid semantic/keyword/entity retrieval, so hybrid search is not an exclusive contribution. Graphiti is the OSS temporal-context-graph engine behind Zep, with source provenance, incremental updates, bi-temporal handling and automatic fact invalidation. Memsys has bounded fact-backed relation expansion, but normal new writes append distinct facts and exact-dedup, with no full automatic semantic superseding. Letta/MemGPT emphasizes agent-managed memory blocks and context management; memsys is a separate recall/source API whose host generates the answer. Own engineering focus is fact/source/span lineage, Qdrant-only online persistence with staged versions/journal/CAS publication and snapshot reads (application protocol, not native multi-record ACID), bounded retrieval/reranking, whole-round working memory with extraction-before-eviction, explicit coverage and scoped logical forgetting. Other systems may also provide similar capabilities; these are scoped design choices, not claims of exclusivity. LongMemEval is a domain-general conversational-assistant long-term-memory benchmark, not a general LLM intelligence suite or medical/finance domain validation. Official README publishes500 instances per variant, five core abilities, six main question types plus abstention suffix. Oracle provides only evidence sessions; S/M contain longer histories and distractors. Oracle is legitimate but cannot establish large-distractor-history retrieval quality or be directly ranked against S/M results. Local historical V7 Oracle32 report is28/32; it is an exposed regression cohort and a historical version, not current blind generalization. Native Mem0 comparison was not completed/scored, so no comparative superiority can be claimed. Cross-framework comparisons must align data version/variant and frozen cases, answer model and declared extraction/embedding resources, context units and budgets, judge/rubric and failure denominators; distinguish end-to-end framework comparisons from component comparisons on frozen facts. Public leaderboard numbers with different conditions are not a controlled comparison. LoCoMo official repo has10 long conversations generated through a persona-based framework with QA/event annotations and named speakers; do not describe all as natural human logs or remap a speaker to an AI assistant. ConvoMem official repo covers user/assistant facts, changing facts, preferences, abstention and implicit connections with configurable evidence/filler mixtures. Local independent24 is a selected/adapted diagnostic plan, not a standard full ConvoMem or LoCoMo official score. Evaluation design: versioned frozen datasets and held-out development split; physically separate source-only write, fixed-question read and gold-only judge inputs with hashes; per-question namespaces, persist source snapshots and outputs, cleanup validation, bounded time/retries, separate judge after answers; distinguish failed, not-run, unscored and wrong states. Layered diagnostics include extraction/source retention, retrieval evidence recall at the actual annotation granularity, context packing coverage, answer accuracy/abstention and operational latency/cost/completion. Do not invent fact-level Recall from session-only evidence labels. Traces join sample/run/model/prompt/source hashes, retrieval candidates/scores, selected/omitted facts and sources. LLM judges need fixed typed rubrics, strict output validation and ideally human calibration/independent judging; current local judge validates completed yes/no labels with bounded format retry and reports judge failures separately, not human-calibrated proof. Faithfulness to supplied context differs from reference correctness. Evaluation architecture references checked: Langfuse datasets/experiments/traces/scores, Ragas retrieval and faithfulness metrics, Promptfoo declarative assertions/provider matrices/CI. These are research references, not existing integrations in this project. Current repository implements a lightweight custom runner, frozen provenance, trace and scorer; proposed production CI/online evaluation or human calibration must be identified as design knowledge rather than completed deployment. No new benchmarks or models were run, no gold case contents were used to tune production, and no production code was changed.
