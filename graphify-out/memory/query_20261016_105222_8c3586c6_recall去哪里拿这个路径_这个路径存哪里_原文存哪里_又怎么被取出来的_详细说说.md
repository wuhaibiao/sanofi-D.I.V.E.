# Q: recall去哪里拿这个路径，这个路径存哪里，原文存哪里、又怎么被取出来的，详细说说

这里的“路径”需要分清楚：**`recall` 返回的是来源记录的编号，不是原文文件的路径。关联关系在写入记忆时就存好了。**

| 名称 | 实际含义 | 存在哪里 |
|---|---|---|
| `/memsys/recall`、`/memsys/sources` | HTTP接口路由 | 服务端代码中定义 |
| `F12`、`E7` | 事实编号、来源轮次编号 | 对应Qdrant里的业务记录 |
| `source_ids: [7]` | “这条事实来自第7号来源”的关联 | 事实记录的 `payload.data.source_ids` |
| Qdrant数据目录 | 数据库内部文件的位置 | 本机磁盘，由Qdrant管理 |

下面用“我现在住在杭州”这个**自编例子**说明，编号仅作示意。

**1. 原文先保存，再建立来源记录。**

收到消息时，程序先把它保存为Qdrant中的 `turn` 记录，字段包括会话ID、角色、内容、时间。整理对话时，再把一轮用户发言及助手回复保存为 `episode`，例如编号为7，对外显示为 `E7`。

这里的 `episode` 是按轮组织的用户和助手文本，**不是LLM生成的事实摘要**。逐条消息仍保存在 `turn` 中。

**2. 抽取事实时，同时保存“事实来自哪里”。**

抽取结果引用输入中的来源轮次；程序把轮次映射到已分配的episode编号，再把编号写入事实的 `source_ids`。编号分配和关联落库由程序完成，不让LLM猜文件路径。见[写入映射](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/write.py:324)和[事实存储字段](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/store.py:525)。

两条记录的业务数据可简化为：

```json
{
  "episode:7": {
    "session_id": "示例会话",
    "user_text": "我现在住在杭州。",
    "assistant_text": "好的。"
  },
  "fact:12": {
    "text": "用户现在住在杭州。",
    "source_ids": [7]
  }
}
```

这里展示的是记录的 `data` 内容；实际Qdrant记录还带有类型、业务key、用户隔离标识等字段。一条事实也可以关联多个来源，例如 `[7, 18]`。

**3. `recall` 从事实记录里读取这些关联。**

假设查询“我现在住在哪里？”，检索、重排后选中了事实 `F12`。随后代码调用 `store.sources([12])`，从Qdrant事实主记录中读出 `source_ids: [7]`，再把7格式化成对外编号 `E7`。

因此返回的事实条目类似：

```json
{
  "key": "F12",
  "text": "用户现在住在杭州。",
  "sources": ["E7"]
}
```

**这个来源编号来自数据库字段，不是模型现场编出的引用，也不是从日志文件里猜出来的。** 见[读取来源字段](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/store.py:595)及[recall返回来源编号](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/core.py:281)。

**4. 调用来源接口，才真正读出原文。**

调用者拿到 `E7` 后，携带用户令牌请求：

```http
POST http://127.0.0.1:8848/memsys/sources
Content-Type: application/json
X-Memsys-Token: <用户令牌>

{"user":"local","keys":["E7"]}
```

服务端会把 `E7` 解析成来源编号7，在当前用户及命名空间内，读取Qdrant中的 `episode:7` 记录，再返回该轮的：

- `session_id`：所属会话；
- `at`：记录时间；
- `user_text`：用户文本；
- `assistant_text`：助手文本。

**当前来源接口直接读取episode中保存的文本，不需要再次向量检索，也不是把向量还原成文字。** 它返回的是该来源轮次，不是自动取出整个历史会话。接口还会限制可返回的记录状态。见[来源接口实现](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/serve.py:737)。

**5. 接口地址和磁盘目录分别来自配置、代码。**

当前记忆服务地址是 `http://127.0.0.1:8848`，客户端把这个基础地址与固定路由拼起来；并不是每条记忆都保存一个来源URL。见[客户端地址拼接](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/client.py:10)。

Qdrant服务地址是 `http://127.0.0.1:6333`。当前原文、事实及关联的主记录统一保存在 **`memsys_records` 集合**，当前命名空间为 `local`。实际磁盘目录是[Qdrant数据目录](</Users/OleniusBlanc227/Library/Application Support/memsys/qdrant/storage>)，由 `qdrant.yaml` 的 `storage_path` 配置。

程序通过Qdrant接口读记录，**不会按 `E7` 去打开某个 `E7.txt` 文件**。同一个来源编号也需要在正确的用户、命名空间和集合下解析。

目前 `recall` 返回关联编号，是否随后调用 `sources` 由宿主程序决定；默认聊天尚未自动执行这次历史原文回查。
