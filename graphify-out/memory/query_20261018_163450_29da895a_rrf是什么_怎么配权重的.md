# Q: RRF是什么，怎么配权重的

## Answer

Expanded from original question via exact graph vocab: rank search retrieval candidate. Current source verified at memsys/src/memsys/read.py:310-328 and config.py:64-66. Reciprocal Rank Fusion combines ranked result lists by summing reciprocal ranks 1/(k+r), with ranks defined here as one-based; absent items contribute zero. It avoids direct comparison of uncalibrated lexical scores and cosine scores in standard form. A common weighted extension is sum_j w_j/(k+r_j); equal w values reproduce standard ranking and weights need not sum to one. k is a rank-smoothing constant, not a channel mixture weight, confidence, or retrieval TopK. Larger k compresses head-rank differences; smaller k emphasizes top positions. The original Cormack Clarke Buettcher SIGIR2009 paper used k60, but this is not evidence of optimality on this project. Current project has no configurable fixed Dense/Sparse 0.7/0.3 mix: for one dense stream and one sparse stream its base score is max(0,cosine)/(60+rDense) + 1/(60+rSparse), with zero contribution from missing channels. Dense therefore has candidate-specific similarity weighting and Sparse has numerator1; this is an RRF-style rank-and-score variant rather than pure rank-only RRF. At equal rank and cosine0.8 the Dense contribution is0.8 times Sparse, not a globally fixed channel ratio. Synthetic example before time/confidence/relation adjustments: A dense rank1 cosine0.9 only =>0.0147541; B dense rank3 cosine0.8 plus sparse rank2 =>0.0288274; C sparse rank1 only =>0.0163934. Fusion order B,C,A illustrates support from multiple lists. Current k60 is configured; the source does not establish that retaining cosine weighting is superior to standard RRF. Subsequent BGE rerank sorts scored candidates by cross-encoder logits with fusion score as tie breaker, not a weighted sum of logit and RRF. General weighting selection should start with an explicit baseline and independent evidence, not claim unperformed optimization. Checked original paper https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf and official Qdrant hybrid docs. No code changed and no evaluations launched.
