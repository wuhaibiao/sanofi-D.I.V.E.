# Q: LLM怎么抽取事实的，为什么选BGE- M3不选其他模型，为什么选Qdrant不选其他数据库，事实去重怎么做，来源关联是什么，持久化怎么做的，可追溯是什么、怎么做

## Answer

图谱词表扩展：[writer, extract, fact, source, store, embedding, vector, schema, duplicate]。当前实现按memsys/src/memsys核验，模型和数据库备选按作者/官方模型卡和文档核验，无新推理、评测或产品修改。
职责：生成式LLM抽取事实实体关系，BGE-M3只提供dense向量，bge-reranker-v2-m3负责联合相关性排序，Qdrant持久化和服务端检索。当前本机配置Embedding为bge-m3-native-fp32，提取角色为现有模型配置；未以具体生成模型品牌论证架构。
抽取：保存消息后按session.turns_done组织未整理完整轮次；会话日期、轮次及用户助手角色输入模型，相关旧事实最多10条及同会话已处理安全消息最多10条只帮助指代，不是新事实证据。EXTRACT_SYSTEM/USER要求JSON entities/facts，text/kind/subject/attribute/value/event_date/rounds/certainty/source_quotes/semantics/relations；记录日期由程序写入。一次正常批次一次抽取，不按长度拆小；截断、JSON或协议错误整批失败保留原文和水位。程序校验值结构、来源轮次、引文定位、关系及别名来源，助手明确列表和Markdown表格确定性回补不另调LLM。格式与引文存在不证明语义正确，不能保证无遗漏或幻觉。坚定计划仍是planned，confidence是firm→0.9的启发式，不是真实率。
Embedding选择：BGE-M3作者卡支持多语种100+、1024维、8192输入、无需给query添加指令；本机服务CLS池化L2归一化，超8192报错不截断。选择理由是中英混合、本机部署、已有适配与长度余量，不声称对其他模型实测最优。E5-large多语种但512且需query:/passage:前缀；Qwen3-Embedding-0.6B支持多语种、32k、可变维度与指令，不能因其较新就排除。中文BGE-v1.5可作为中文基线。当前Sparse是terms+哈希词项+TF和Qdrant IDF，不是M3 learned sparse或ColBERT，也不宣称标准BM25。更换同维模型仍需用已存事实重建向量，不需重新做LLM事实抽取；Recall/MRR/延迟内存需要同条件比较才能得出优劣。
数据库：Qdrant提供向量+payload过滤，namespace+user_id租户标识、状态和发布版本筛选，与当前本机REST集成一致。原文、事实、来源、实体关系用records无向量payload保存；dense_dimension、lexical、jobs分别存dense、词法和任务。Postgres+pgvector有原生事务JOIN与向量，是业务状态事务密集时很合理的备选。SQLite WAL读写可并行但同一时刻单writer，不能说不支持多用户；FAISS是向量库须另配业务存储；Milvus也支持混合检索，没有性能对照可排除它。Qdrant并非唯一或实测更快的选择。
去重：消息幂等键防网络重复，键同但正文不同报错；_dedupe按fact_identity做批内合并rounds/quotes；跨批Store.exact_fact用strip(text)SHA256定位候选，再比text、value、kind、subject、attribute、event区间精度、semantics、relations完整身份。结构化JSON排序规范化但不是语义等价归并。重复关联新来源，不提高置信度；未锚定事件跨会话/来源轮不凭同描述合并。同义改写可能留多条，新旧值不同另存，当前新增不自动覆盖/生成superseded链。
来源关联：LLM rounds映射到本次episode编号，事实payload.source_ids保存多对多来源。source_quotes用round/role/quote检查相应episode角色文本唯一出现，再计算相对start/end、记录原quote；失败不保存精确span，轮次级来源可仍保留。F事实→E轮次→session/role/at/原话；同事实多个来源。POST /memsys/sources接受E编号返回该租户可见active/archived安全来源。默认事实模式不自动展开来源。来源支持核对、迁移重建、去重后保留依据以及主动遗忘的安全屏蔽；不能把源引文匹配当成语义蕴含证明。
持久化：Store.append_turn即写原文/会话/幂等receipt；模型调用与Embedding在短提交外准备。Store._commit prepared日志→不可变payload和dense/lexical版本→对租户head旧revision条件更新+update_only切换发布点→committed；同批事实来源关系索引与处理水位在应用协议中一起发布。读固定head并检查最新可见版本，失败发布暂存不可见；发布后marker前崩溃可由head识别，下次finalize。普通head冲突复用模型结果，事实revision/水位变动则重新准备。是应用协议非SQL多表事务，单租户仍竞争head。Qdrant自身WAL和磁盘存储管理底层恢复。实际/Users/OleniusBlanc227/Library/Application Support/memsys/qdrant/storage存在；配置及部署脚本固定路径。提供Store.backup导出，不因snapshots目录存在声称自动定时备份。
追溯分两层：出处F→source_ids E→角色原文/会话日期/精确span；过程评测question_id/corpus/session关联抽取快照、候选、重排、selected/omitted、最终prompt、模型账本、答案和judge。存储revision和模型/索引指纹帮助查版本，不等于自动知识更新链。能检查送入模型的证据，不能证明模型内部实际推理。示例可自编2026-10-18明确计划11月6杭州星河项目评审，事实event_date=2026-11-06、状态planned、角色评审人、记录日期10-18，F101/E21均为说明编号非真实评测样本。
