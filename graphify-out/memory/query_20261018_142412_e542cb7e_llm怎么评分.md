# Q: LLM怎么评分，

## Answer

扩展词来自图谱词表：[judge, grade, gold, label, answer, prompt]。当前评分代码以 src/memsys/bench/judge.py 和 scripts/evaluate_public_types.py 为准。
评测采用LLM语义二分类：回答生成并保存后，评分阶段才读取冻结judge-inputs中的原题、参考答案/评分细则和已生成hypothesis；将三者按题型填入anscheck_prompt。裁判只输出yes/no，不负责重新查询原会话或评价抽取与检索各模块。普通用户/助手/跨会话题要求包含完整所需答案，语义等价或包含充分中间步骤可判yes，部分信息no；时间推理对天/周/月等时长差1容错；知识更新允许带旧信息但需有正确更新答案；偏好题依rubric正确回忆并利用个人信息，不要求逐点覆盖；拒答题要求识别不可回答而非编造。
_grade发purpose=judge并带question_id/judge_attempt。严格匹配yes/no（大小写不敏感，允许末尾句点或感叹号）；输出截断或格式不合法时只增加一次格式重试，原答案不修改。阻止/拒绝或仍无效抛错。evaluate_public_types.judge保存graded/correct/actual_model/attempts，回答失败记answer_error,false；判分异常记judge_error,correct=None。正确数按true统计，选定总题数作分母，答题失败保留；判分错误另列评分未完成，不能伪装为有效裁判no。
CapturedChat与UsageLedger捕获judge提示、题号、阶段会话和token/延迟。当前models.chat or models.memory沿用回答模型，同模型偏差仍在；阶段与进程隔离能隔开上下文，不保证裁判公正。当前生产记忆/回答链路没有每轮调用裁判。全部内容仅代码核验，没有读取任何实际评测参考答案或启动评测。
