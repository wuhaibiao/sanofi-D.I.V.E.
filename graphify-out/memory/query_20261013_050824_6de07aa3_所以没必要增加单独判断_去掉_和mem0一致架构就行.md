# Q: 所以没必要增加单独判断，去掉，和mem0一致架构就行

## Answer

主流程已改为参考 Mem0 的单次抽取、去重、新增：相关旧记忆和新消息进入同一次抽取；MemoryInserter 只做精确文本去重与新增，不调用 LLM、不自动取代旧事实。跨会话重复通过索引 content_hash 检索，旧记录通过 data.text 精确过滤兼容，最终核对最新记录状态，避免遗忘或过期存储版本复活；重复来源关联保留，不提升置信度。后台补抽同样无裁决步骤。配置与部署模板默认 query_analysis=false/query_policy=off；roles.resolve 退役并告警后忽略。原有原文、来源、Qdrant 与旧版本链继续保留。每个正常有界抽取块一次生成式 LLM，分片、输出重抽和任务重试另计；默认检索不调用生成式 LLM；最终回答由宿主 Agent 生成。49 个合成功能检查和 1 个临时本机 Qdrant 的精确去重/旧记录/遗忘过滤集成检查通过；没有评测、性能测试或真实 LLM 请求。新版源码部署包 dist/memsys-cloud-additive-20261012.tar.gz 已生成并逐文件比对，Python wheel 已构建。deploy/use_additive_memory.py 会先保留私密配置备份，再移除旧裁决配置、关闭额外规划和复查，保留模型端点、密钥、挂载 inode 并设置容器可读权限。README 有现有 Caddy 部署更新命令。云端未被远程修改，需要用户上传包并重建 memory。Graph orientation used memsys_write_writer and memsys_update_updater from old graph; source locations memsys/write.py:L266 and memsys/update.py:L69 are historical. Actual current source verified in src/memsys/write.py, update.py, store.py, config.py, prompts.py and tests/test_additive_write.py. The graph's old Updater flow is retired.
