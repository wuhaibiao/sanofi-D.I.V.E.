# Q: 为什么父块总是超预算，不能调大一点吗

## Answer

沿用此前从图词表展开的 chunking chunks parent retrieval reranking budget eval，定位 parent_excerpt()、episode_excerpt() 后用冻结源码和 v19 实验校验。父块768个真实BGE token，但单条摘录1800、总记忆3500、完整回答8192均是UTF8字节，事实和标签还消耗剩余总预算。350次父块超预算尝试退回局部摘录；关闭父块还原后48题最终记忆完全一致，因此长父块挤掉证据的解释未获支持。可以调大，实测单条4000/总记忆7000/完整输入16384使父子正确数37/48降到33/48，固定方案38/48降到36/48。总预算还控制取证分页，页变大后部分取证、计算与推理失败。仅增单条上限父子仍37/48，细子块96/12为36/48，修改取证修复提示仍37/48，均无净提升。固定查询计划及完全相同请求响应后原父子与固定只差1题，历史6题差距不能全归因于分块。新抽6题固定3/6父子2/6，样本过小。实验结果详见 memsys/docs/chunking-validation-v19.md，未切换生产默认配置。
