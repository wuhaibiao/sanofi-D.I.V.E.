# Q: 目前记忆以什么形式返回给agent

## Answer

Expanded against existing graph vocabulary [memory, context, proxy, render, recall]. Verified main core.py 188-229, serve.py 715-725 and 800-810, read.py 756-821, prompts.py MEMORY_CONTEXT and fact_content.fact_text, plus MemoryClient.recall. HTTP POST /memsys/recall returns a JSON object containing context, memory, rules, items, trace_id, tier, coverage, revision, relations and coverage_supplement. context is the ready-to-inject formatted long-term memory string: heading # Long-term memory, Today is date, rendered selected facts and memory-use rules. memory contains only rendered selected fact content; rules contains the separate instructions; items holds machine-readable selected facts including identity, date/status, subject, attribute, value, semantics, relations, sources and confidence. Current proxy injects only rec.context wrapped in <memory> tags at the front of the latest user message before forwarding; it does not inject the entire duplicate REST response. The web host instead puts recalled context inside a retrieved_memory block in its system prompt. Format is semi-structured plain text/Markdown, not just one-sentence memories: grouped facts contain identifiers, noted/event dates and state, memory_kind, explicit scope/event identity and qualifiers. Structured lists/tables/fields may appear as JSON after Value and grounded relations as JSON after Relations. Shared structured values can reference an earlier fact instead of repeating the JSON. Default facts mode excludes raw conversation excerpts. Recall does not generate a new summary or final answer; the host agent generates the answer. Final explanation should distinguish transport JSON from actual model-visible text and label any abbreviated example as schematic. No source edits, evaluations or remote model calls.
