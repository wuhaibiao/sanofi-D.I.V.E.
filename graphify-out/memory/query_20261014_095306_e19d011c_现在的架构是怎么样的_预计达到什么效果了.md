# Q: 现在的架构是怎么样的，预计达到什么效果了

## Answer

Expanded via graph vocabulary: Writer Fact Recall Store MemoryService. Existing graph is older; current source, private configuration (without exposing credentials), live authenticated status and already published aggregate results were verified.
当前系统是结构化事实记忆服务，宿主Agent生成最终答案。写入：原始消息先保存到Qdrant，会话关闭或达到阈值后后台整理，检索相关旧事实，同一批正常只调用一次GPT-6 Luna抽取。确定性解析器补充明确的助手编号列表及Markdown表格；列表保留名称、原编号和短动作，表格保留单元格。完整字段一致才去重，不同值、条件和事件分别追加；不自动裁决取代旧记忆。完整value、主体、属性、条件、事件及记录时间和来源进入事实存储与输出。
读取：当前问题经本机BGE-M3向量及词法检索、融合、时间/状态/置信度加权、本机MPS float32 BGE重排，再按预算选择完整事实。预算不足移除整条，不截碎value。默认recall_mode=facts，不展开来源原文，不补跨会话待整理原文；当前对话仍保留最多12条消息并受完整输入预算约束。网页宿主一次生成答案，不统一复查。Qdrant是唯一在线存储，记忆API、本机Embedding、BGE重排在本机，抽取及回答LLM为外部GPT-6 Luna。当前记忆预算32000、完整输入65536，budget_mode为UTF8字节而不是模型token。正常读取无额外LLM查询规划。
实际工程证据：118项相关功能测试，8项新增无答案隔离测试；当前本机local账户无排队、重试和失败任务。旧24题仅事实21/24，修复及结构回补后23/24；预选额外24题21/24。这些均按开发/修复回归管理，不能预测未知题正确率，完整当前版本未做新独立端到端盲测。两批长期记忆原文摘录为0。原24题回答输入tokens42917升到88385，平均完整读取与回答耗时5.79升到9.12秒，额外24题约7.47秒；增加信息保真有成本，并非同时提高效率。
可合理预期：跨会话已整理事实的查询，精确数值和明确列表/表格关系更少被字段裁剪丢失，原文可追溯，正常生成调用数可控。不能保证抽取完整、精确历史事件时间解释、个性化建议采纳或大规模并发表现。当前阶段是可用的记忆服务原型；泛化正确率未知。以后依据通用需求与自编场景改进，不依据评测答案调参。
