# Q: 为什么要固定分块，不是语意分块，或者父子分块

## Answer

图谱扩展词：[chunk, semantic, budget, indexing, episode, retrieval]。当前源码是角色+长度预算原文分段，事实逐条编码；facts默认不检索episode/chunk，因此原文分块是诊断/来源索引策略，不能拿它直接解释默认事实召回准确率。按角色先划分，长度预算内优先段落换行空格，无额外语义边界嵌入和阈值决策，来源区间直接映射。当前384单位UTF8字节，不是BGE token，这个大小没有被证明最优。
概念：固定/语义是切分边界策略，父子是小块检索、大父块扩展的粒度组织，可以把语义父块再切固定子块。语义常用相邻句子/句组embedding差异选阈值，不必调用生成式LLM；增加句段编码、缓存、阈值与语言句界处理，不能保证指代/时间状态/限定条件完整，也需最大长度约束。父子适合小片段无法独立理解时扩展上下文，代价是维护映射、去重、版本/遗忘规则和回答预算，收益取决于父块是否实际送入回答。当前chunk→episode映射已有，并按episode聚合、诊断模式取命中摘录，不等于默认启用连续主题父块自动扩展。
历史证据仅分析文档而未读实际题目答案：docs/chunking-validation-v19.md是2026-10-10旧原文混合链路的开发回归，固定原预算38/48，父子原预算37/48，改善2退步3，McNemar p=1，不足以证明固定更优；关闭父块展开后48/48最终memory相同，不能归因大父块实际挤占证据。大预算同时影响分页，不能单归因父块。docs/rag-refactor-assessment.md记录语义边界只做机制/缓存验证，没有D完整配对问答验证；不能称语义方案已测准确率较差。已退役相关生产能力，冻结代码留存。
为什么当前保留：主索引语义粒度由抽取事实承担（这不是把事实抽取等同语义分块）；原文辅助索引优先确定性、按角色来源可定位和有限编码规模；旧父子方案未显示稳定收益，不增加默认复杂度。不把384字节或无重叠描述为已验证最优，强截断仍可切句，短块可能缺上下文，长结构化事实未分块是另一个问题。若将来长原文直接参与回答并确认边界缺上下文是主要错误，再考虑句段结构/语义边界/有界父块扩展；不自动新增评测或修改系统。官方解释参考LlamaIndex Semantic Chunker和LangChain ParentDocumentRetriever。
