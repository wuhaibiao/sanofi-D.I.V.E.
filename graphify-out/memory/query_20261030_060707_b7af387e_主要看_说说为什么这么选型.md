# Q: 主要看、说说为什么这么选型

## Answer

最关键的选型，是**在写入时整理信息，还是在回答时理解原文**。

- **主方案选择结构化事实**：希望提前整理人物、事件、时间和状态，方便后续更新、聚合与检索。代价是增加抽取调用，抽取遗漏也会传到答题阶段。
- **当前分支选择原文分块**：针对已经反复出现的抽取漏存，保留原话、列表和限定条件，同时省去生成式抽取。代价是回答 Agent 要承担更多对象识别、时间关联和信息整合工作。

其他技术选择服务于这条处理链：

| 选型 | 为什么选、放在哪里 | 取舍 |
|---|---|---|
| **Qdrant** | 集中保存正文、元数据和向量索引，承接持久化与混合检索，减少多套存储的同步工作。[官方文档](https://qdrant.tech/documentation/search/hybrid-queries/) | 已有 PostgreSQL 的项目也可以采用 pgvector；当前没有证明 Qdrant 必然更优。 |
| **BGE-M3 嵌入** | 支持多语言和较长输入，适合对话原文；写入时编码记忆，提问时编码查询。[模型说明](https://huggingface.co/BAAI/bge-m3) | 需要本地推理资源，换模型通常需要重建向量索引。 |
| **向量＋词项召回，RRF 融合** | 向量匹配同义表达，词项补充姓名、名称和原词匹配；按名次融合，避免直接混加不同尺度的分数。[机制说明](https://qdrant.tech/documentation/search/hybrid-queries/) | 两路都会带来无关候选，后面仍需筛选。 |
| **本地 BGE 重排** | 在初召回后联合读取问题与候选，细化排序；只处理少量候选，并省去远端生成式筛选调用。[模型说明](https://huggingface.co/BAAI/bge-reranker-v2-m3) | 本轮平均耗时约 10.9 秒，是主要本地开销，是否值得保留要看质量收益。 |
| **名次融合＋重复内容软降权** | 保留初召回和 BGE 两种排序信号，减少相似长回复挤占返回位置；全部由本地计算完成。 | 属于当前实现取舍，等权融合没有被证明是最优权重。 |
| **补同轮原问、恢复原顺序** | 给命中的助手回复补足用户条件和指代，再按原轮次排列，帮助 Agent 理解上下文。 | 会增加输入；最长只补一个块，仍可能缺少完整语境。 |

**目前支持这个方向的是成本收益，质量还没有超过主方案。** 同组开发回归中，生产生成调用从 53 次降到 20 次，原始判分为主方案 19/20、当前分支 18/20；其中还有一题评分一致性疑点。这支持继续验证“省去抽取、加强原文检索与返回”的路线，尚不足以确定替代主方案。[评测记录](/Users/OleniusBlanc227/Documents/sanofi/memsys/runs/raw-chunk-context20-20261029/report.md)
