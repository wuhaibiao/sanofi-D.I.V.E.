# Q: 记忆更新遗忘怎么做的

## Answer

Expanded from original query via graph vocab: update forget retention lifecycle fact store. Existing graph is stale, so graph nodes were used to locate current memsys/src/memsys source. Current update.py MemoryInserter performs deterministic exact text plus identity dedup; qualifying duplicates only append source associations and do not strengthen confidence or change old content/status; different text is inserted as a separate dated fact. Unanchored events cannot be merged across observations solely on identical wording. Normal writes do not automatically supersede contradictions; legacy supersede/confirm support is not the current normal write pipeline. lifecycle.py retention is 0.45 importance + 0.35 recency + 0.20 log-normalized usage; recency is 0.5^(idle days/90), and fact scores multiply by 0.6+0.4 confidence. Default/deployed automatic archive requires at least 180 idle days AND score below 0.2; active caps 5000 facts and 2000 episodes archive lowest scores. Referenced sources are protected from ordinary idle archival, not necessarily from the capacity pass. Lifecycle runs after close_session or explicit maintain, not just passage of wall-clock time. Archived entries are eligible for historical, enumeration or insufficient-candidate fallback. Explicit forget marks facts or episodes forgotten, updates derived chunk eligibility, clears backlog, and prevents associated originals and processed conversation turns from reintroducing forgotten values using validated safe views or conservative whole-source withholding. Forgetting an episode also forgets source-orphaned facts. Relation expansion validates eligible fact witnesses rather than physically erasing all relation records. This is logical forgetting, not physical erasure of original payloads, retained versions, exports or prior traces, and does not guarantee global semantic-paraphrase erasure. Parameters are configured heuristics; code alone does not establish optimality or measured retrieval gains.
