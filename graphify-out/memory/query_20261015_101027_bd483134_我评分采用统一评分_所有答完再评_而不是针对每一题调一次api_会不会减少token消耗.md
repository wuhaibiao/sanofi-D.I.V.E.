**把多题合并进一次API请求，可以减少重复评分规则的输入 token；但不会按调用次数等比例节省。**

目前代码已经是“全部回答完，再统一启动评分”，只是评分阶段仍然逐题调用API。仅改变评分时间，不会减少 token。

真正合并请求后：

- 公共评分规则可以只写一次。
- 每题的题目、标准答案、模型回答仍要传入。
- 仍需输出每题判分，批量结果的题号和JSON格式还会增加一些输出 token。

旧32题评分共 **7,424 token**，占抽取、答题、评分三阶段文本 token总量约 **0.73%**，所以对整轮 token的节省空间较小。这是token占比，不是费用占比。见[用量记录](/Users/OleniusBlanc227/Documents/sanofi/memsys/runs/relational-memory-v7-32-20261014/summary.json)。

开发评测可以采用**同题型每批4题**：32题约8次请求，共享评分规则，只返回“题号＋判分”。这能减少请求次数，同时便于检查漏题和错位；实际净省多少 token还需测量。批量评分属于新的评分协议，应与原逐题评分结果区分记录。
