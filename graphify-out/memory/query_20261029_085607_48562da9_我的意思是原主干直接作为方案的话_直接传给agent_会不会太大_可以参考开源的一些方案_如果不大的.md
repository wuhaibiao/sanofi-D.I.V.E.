Recommendation: prefer main as the integration baseline for an agent with substantial remaining capacity in a 128000- or 200000-token window; the measured sample size does not justify requiring the Top-20 experimental refactor. Historical main full-answer input averaged 9305.85 and peaked at 25344 tokens, corresponding to 7.27/19.8 percent of an illustrative 128000-token window or 4.65/12.672 percent of 200000. These are full evaluation prompts including memory/rules/system/current question, not exact marginal memory injection into an arbitrary agent, and do not include that agents existing code/tool/history workload. At 32000 tokens this input is relatively heavy. Main recall context alone has mean 40418.75 UTF8 bytes including about 5927.8 bytes fixed wrapper and rules, exact tokens depend on target tokenizer. Current proxy already injects only rec.context at serve.py 810; REST returns redundant context/memory/rules/items, so direct agent wrappers should expose only the needed context. A lightweight adapter and deduplicating existing instructions suffice as proposed integration work; keep extraction, BGE, source/temporal ordering and recall breadth unchanged. No product code edits, configuration changes or deployments were performed. Open-source primary sources checked live: Mem0 README https://github.com/mem0ai/mem0/blob/main/README.md blob c9ed6dbfbe14a2fe60b8f3761a083786157a6987 uses memory.search(... top_k=3), joins each result memory text, and inserts that text in the system prompt; this is an example parameter, not a universal size rule. Shared pattern is keeping full durable memory outside the prompt and returning relevant context, which main already implements; these systems have different item granularity and their K values cannot be converted to comparable token sizes.
