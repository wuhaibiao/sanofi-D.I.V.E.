# Q: 为什么抽取时要结构化，直接对文本分块向量化不就行了吗

## Answer

可以，直接对原文分块并建立向量索引是成立的基础路线，结构化抽取不是必要前提。向量用于定位，命中后返回对应原文片段给agent；原文需要单独保存，不能把embedding本身当作无损存储。LlamaIndex VectorStoreIndex 的基础流程将文档切成带元数据的文本Nodes后建索引，不要求先抽取事件或关系事实，见 https://developers.llamaindex.ai/python/framework/module_guides/indexing/vector_store_index/ 。
原方案采用结构化，是为了统一用户资料、偏好、对象、事件时间及状态，方便去重、状态更新和跨会话统计，并期望减少返回上下文。实际问题在于将有损抽取结果作为唯一答题入口，丢失的起始事件或原因无法从原文补回。当前源码已具备按角色分块的原文向量能力（src/memsys/indexing.py:27），写入阶段抽取事实后会同时向量化事实与活跃原文块（write.py:307,354）；本轮frozen配置episode_chunk_vectors=true但recall_mode=facts，read.py:416排除了原文，因此并非没有原文索引。
本轮30题相关原文正文总606441字节，平均20214.7字节；返回memory平均33929.87字节，含事实元数据；memory加规则平均39857.8字节。原文数值不含时间角色等头信息，两种内容口径不同，不是严格压缩率或同质量比较；这些数据不能支持结构化必然节省窗口的承诺。
建议把原始消息加会话时间、角色和会话ID保留，按自然段或完整对话轮分块，使用向量加关键词检索及本地BGE重排，返回命中的有限原文片段和必要邻域。LlamaIndex也有小块检索、回到较大父块取上下文的实现，见 https://developers.llamaindex.ai/python/framework/integrations/retrievers/recursive_retriever_nodes/ 。结构化事实保留为可选辅助层，收益需同预算真实对照证明。直接分块消除了抽取前置漏写这一步，但仍可能检索漏块、切断因果、混淆新旧状态或在生成时漏用证据；计数全量问题也不能仅凭Top-K保证完整。目前没有纯原文基线与当前结构化方案的严格同条件结果，不能承诺正确率或费用改善幅度。此轮只核对代码、已有评测数据和官方文档，没有改动生产或评测。
