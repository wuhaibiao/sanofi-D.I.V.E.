## Answer

Expanded from original query via vocab: [model, embedding, reranking, store, server]. Inspected deployed configuration via an explicit non-secret field whitelist, current source, dependency metadata and read-only health endpoints; no model inference or source edits. Live Qdrant reports1.19.2, embedding weights loaded, memory service ready. Python3.12.14; torch2.14.1, transformers4.57.6, tokenizers0.22.2, numpy2.5.3, sentencepiece0.2.2. Deployed roles memory/extract gpt-6-luna over OpenCode Responses; embedding bge-m3 local; rerank bge, MPS FP32 batch4, max512. Lexical retrieval is TF+server IDF, not equivalent to BM25 or BGE-M3 learned sparse vectors.
当前系统的核心是 **Python＋Qdrant＋gpt-6-luna＋BGE-M3＋BGE Reranker**，记忆管理和检索编排由项目代码实现。

目前使用的模型如下：

| 模型 | 用途 | 运行位置 |
|---|---|---|
| `gpt-6-luna` | 抽取事实、实体和关系，以及生成最终回答 | 经 OpenCode API 调用 |
| `BAAI/bge-m3` | 将问题和记忆转换成1024维稠密向量，用于语义检索 | 本机 Python 服务 |
| `BAAI/bge-reranker-v2-m3` | 对“问题＋候选事实”重新打分、排序 | 本机，当前使用MPS、FP32 |

此前小评测的裁判也使用了 `gpt-6-luna`；它是评测角色，不是新增的一种记忆模型。

工程技术栈是：

| 层次 | 当前实现 |
|---|---|
| 后端 | Python，当前环境为3.12；标准库HTTP服务、线程与后台任务队列 |
| 存储 | Qdrant 1.19.2，保存原文、事实、实体关系、向量和任务记录 |
| 模型推理 | PyTorch、Hugging Face Transformers、Tokenizers、SentencePiece |
| 数值计算 | NumPy；本机模型使用Apple Silicon的MPS加速 |
| 网页 | 原生HTML、CSS、JavaScript |
| 接入与部署 | REST、Python API、MCP及模型代理；macOS原生进程与launchd管理 |

依赖和部署入口见[依赖配置](/Users/OleniusBlanc227/Documents/sanofi/memsys/pyproject.toml)及[本机部署代码](/Users/OleniusBlanc227/Documents/sanofi/memsys/deploy/local.py:66)。

记忆层还实现了这些技术：

- **混合检索**：稠密向量＋TF/IDF词法稀疏检索，再做排名融合和BGE重排。
- **实体关系索引**：由LLM抽取、程序管理，存入Qdrant，支持最多两跳的有界扩展；当前没有单独部署图数据库。
- **记忆组织**：近期工作窗口、结构化长期事实、来源关联、去重、遗忘和上下文预算控制。
- **评测与追踪**：LongMemEval、unittest、JSON/JSONL记录，以及输入、源码和配置哈希。
