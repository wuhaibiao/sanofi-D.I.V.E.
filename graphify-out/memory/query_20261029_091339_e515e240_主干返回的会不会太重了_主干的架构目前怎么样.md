# Q: 主干返回的会不会太重了，主干的架构目前怎么样

## Answer

Expanded against actual graph vocabulary [memory, context, proxy, extract, rerank, budget, core]. Inspected live main core.py recall/_retrieve, read.py search/rerank/select/render_memory, write.py consolidate/_extract/literal fallback/indexing and serve.py REST/proxy injection. Assessment: payload presentation is fairly heavy although capacity is acceptable as a baseline for a large-window agent with room; core architecture need not be replaced merely because returned text is verbose. Main writes raw turns, performs background batch extraction in separate model requests, preserves literal tables/lists and source-backed facts, grounds relations and indexes data. Read path uses heuristic query planning by default, query embedding, dense/lexical fusion and local relation expansion, BGE reranking, source-aware ordering, temporal/current-state handling and advice grouping, bounded fact selection and optional coverage packing, then renders context for a host agent to answer once. Default facts-only recall excludes raw conversation excerpts; recall itself neither summarizes with another LLM nor generates the final answer, and no answer-audit gate is used. Current proxy injects only rec.context, so REST JSON duplicate fields should not be incorrectly counted as duplicated current model input. However REST context/memory/rules/items are redundant if a tool wrapper blindly returns all fields. Observed payload has mean facts 34490.95 UTF8 bytes plus about 5927.8 bytes rules/wrapping, mean context 40418.75 bytes, not native model tokens. Actual historical full answer prompt mean 9305.85 and max 25344 tokens includes system/current question, not exact marginal memory cost. Fixed MEMORY_RULES is 5875 bytes. Each fact can carry dates, source class, object/event identities and conditions plus prose, a structured JSON Value and grounded Relations; some overlap can be simplified but these fields can carry distinct essential assertions and cannot be dropped indiscriminately. Main retrieval mean candidate facts 39.05 and selected 37.95 indicates limited volume shrinkage in this cohort, not measured irrelevance or precision; ordinary/all/supplement final caps are 30/60/up to 128. A list/table can be a large single fact, so count alone is not an input-size guarantee. Small exposed historical raw 19/20 is a usable regression reference, not architecture generalization or production maturity proof; write omissions, role/time mismatch and generation ignoring goals remain quality risks. Recommendation: retain main storage/extraction/BGE/source-time ordering and fix presentation independently, preserving full stored data, exact values/list/table associations, relevant role/time/state/qualifiers in agent context while reducing repeated instructions and provably duplicated representations. Do not prioritize further Top-K shrinking or add another summary/selector/reviewer generation. Keep hard audit gates removed. No product changes, new evaluation or model calls were performed.
