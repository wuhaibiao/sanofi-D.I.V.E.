# Q: 工作窗口不是短期记忆吗，，结构化长期事实是长期记忆吗，原文什么时候用，存哪里，怎么取

## Answer

Expanded from original query via vocab: [memory, source, session, store, client]. Directly verified deployed collection_prefix=memsys and namespace=local without reading user content, raw turn/episode records, working-window selection, recall source IDs and HTTP sources handler. Working-window messages are selected from persisted source turns, not an independent durable memory store. Sources API accepts E IDs (not F IDs), requires existing user token, returns role-separated round text; default facts-only answering has no automatic raw-history fallback. Read-only inspection; no user data/model calls or code edits.
对，你理解得对。我上一条把“整个记忆系统的组成”放在长期记忆里讲，容易混淆，应该分开：

| 部分 | 定位 | 如何使用 |
|---|---|---|
| **工作窗口** | 短期／工作记忆 | 选取当前会话近期完整对话，受轮数和token预算限制，直接进入上下文 |
| **结构化事实** | 长期记忆 | 保存个人信息、偏好、事件等，跨会话按需检索 |
| **原文档案** | 持久化的来源底稿 | 用于抽取、补抽、查看历史和溯源，默认不作为历史问答证据直接召回 |

工作窗口是从已经保存的消息中临时选出来的，因此“短期”不表示这些消息没有落盘。

原文现在存放在**本机Qdrant的 `memsys_records` 集合**，按记录类型区分：

- `turn`：逐条消息，保存会话ID、角色、内容、时间。
- `episode`：整理后的对话轮次，带 `E…` 来源编号。
- `fact`：抽取后的事实，通过来源编号关联原文。

底层文件由Qdrant管理，位于[本机数据目录](</Users/OleniusBlanc227/Library/Application Support/memsys/qdrant/storage>)。

原文主要在**整理成事实、失败后补抽，以及明确查询历史／来源**时使用。

取原文的现有路径是：

1. 调用 `/memsys/recall`，取得事实以及它的 `sources`，例如 `["E7"]`。
2. 携带用户令牌调用 `POST /memsys/sources`，传入来源编号，示意：
   ```json
   {"user":"local","keys":["E7"]}
   ```
3. 接口返回该轮的 `session_id`、时间、`user_text` 和 `assistant_text`。见[接口实现](/Users/OleniusBlanc227/Documents/sanofi/memsys/src/memsys/serve.py:737)。

**当前普通回答使用“近期工作窗口＋召回的长期事实”；即使事实抽取遗漏，也不会自动回查历史原文补答案。来源查询接口已有，自动原文兜底尚未接入。**
