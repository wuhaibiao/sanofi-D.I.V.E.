# Q: mem0怎么做的，我的方案和他有什么不同

## Answer

Mem0 默认写入也会调用 LLM 抽取记忆。你的方案多出的主要环节，是单独判断新旧事实关系，并维护事实状态、来源和版本。两阶段抽取与裁决是我们自己的实现选择，需要单独说明理由。

当前 Mem0 开源 Python 基础写入流程：收到消息与用户标识；取得最近 10 条消息并检索约 10 条相关旧记忆；一次 LLM 抽取；Embedding；文本哈希去重；保存新增记忆与历史。infer=False 可以跳过生成式抽取。当前 add 采用新增策略，不自动覆盖或删除旧记忆；显式 update/delete/history 另有接口。

你的流程：原文及时保存到 Qdrant；达到阈值或会话结束后台抽取；按每条新事实的主体、属性及向量找旧事实；有旧候选时批量调用 LLM 判断新增、重复、取代、独立事件或存疑；检查结构与版本后提交来源与状态。有旧候选并不等于确有冲突。

普通路径调用数不含重试和分片：Mem0 一次 add 通常 1 次生成式 LLM，基础 search 0 次；我们每个抽取块 1 次，有旧候选再增加裁决批次，查询规划按条件 0 或 1 次。Embedding 和 BGE 重排是另计的模型计算。最终回答由宿主 Agent 生成，两者都没有必需的最终答案审查。

Mem0 当前 SDK 将最近消息和修改历史保存于 SQLite；recent messages 每个 scope 只保留最新 10 条，这不等于它没有历史，也不等于完整原文长期归档。我们的在线数据全部 Qdrant，持久保留原文与来源引用、事实取代关系及任务。仅仅全用 Qdrant 不证明更快；提交一致性和持久任务需要应用自己维护。

Mem0 当前基础 search 已有向量、可用的关键词 BM25 与实体信号、可选重排；混合检索并不是我们独有的能力。我们额外有事实状态与时间处理、来源分页和可选查询规划。

例如杭州搬上海：当前 Mem0 add 可新增搬家信息，但不会自动将杭州记录标为被上海取代；调用方可用 update 修改。我们在模型判断为取代且提交成功时，将旧事实 superseded、新事实 current，并保存来源及关联；结果仍依赖抽取和关系判断。

我的判断：如果主要需要跨会话记住偏好与背景，Mem0 基础流程更直接；如果明确需要当前状态、历史沿革与完整追溯，现有扩展有用途。保留来源与版本并不必然需要第二次 LLM；这两个模型步骤可以考虑合并，复杂查询规划也应按需求决定。不能将模块更多当作质量更高或成本更低的证据。
