# 评测完整性

用户要求：系统改进不得针对评测题或标准答案定制；不得根据答案改写问题或选择容易答对的题目。

- 不查看评测参考答案来设计或修改生产提示词、抽取、检索、重排、路由或过滤规则。以通用功能要求和自行编写的场景验证实现。用户明确要求的完整性审计可以核对既有记录，但不能把审计中看到的题目或答案继续用于产品调参。
- 制样程序可以机械分离并冻结数据字段，不能根据标准答案或表现选题；标准答案仅用于独立评分和用户授权的完整性审计。模型写入阶段使用不含评测问题和答案的历史输入文件；答题阶段使用固定原题和已存事实，不能读取标准答案文件。公共评测使用 `scripts/blind_eval_inputs.py` 的字段白名单、冻结哈希和阶段隔离；旧工具须先符合相同隔离要求才能用于新的验证。
- 不修改原题、不把标准答案作为提示或事实、不按已有得分挑题、不选择性重答失败题或改写标签。原始错误及中间结果均需保留。
- 已查看题目、参考答案或据其失败调整过系统的集合只能作为开发回归。评测过的预留题集不能继续声称是未使用的盲测；不根据该集合的逐题反馈改进下一版本后又用它证明泛化。
- 题目专名、编号和参考答案可以保存在隔离的结果与审计数据中，不能成为生产规则或报告脚本中的硬编码常量。报告脚本只能读取既有结果数据，不向模型传入这些数据。
- 不自动增加其他评测集、消融实验或500题验收。当前用户已明确排除后两项。
