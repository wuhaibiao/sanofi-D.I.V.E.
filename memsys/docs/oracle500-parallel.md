# 500题评测并行接管

用户要求将本轮评测改为多个worker。新增 `scripts/run_oracle500_parallel.py`，仅修改调度层；原始产品源码、模型、提示词、输入和事实索引策略保持冻结。

调度支持2到4个题目worker，用户随后明确选择本轮使用4个。每题分别写入、审计、回答和清理。读取及BGE重排阶段用共享信号量限制为1个并发；本地embedding继续使用既有单服务，不在worker中重复加载该模型。

接管在当前题的read子进程运行时暂停原控制器，让子进程完成原有回答。验证回答和read摘要完整后清理该题集合，保留原始响应与失败，归档串行执行状态，然后封存并行调度计划。接管不会重答、重抽、修改已完成题目，也不会按结果挑选后续题。

`parallel-plan.json` 保留原冻结文件哈希、新调度器哈希、已完成范围、已保留文件哈希和外部集合名单。原 `freeze.json` 不改写。并行清理只匹配本题精确前缀，对其他worker集合的存在和合法清理不报误删。

只有全部题目完成回答阶段且集合清理核验通过，才开始统一评分。原有未能作答的题保持失败记录。报告补充串行完成范围、并行worker数和调度变更说明，明确这轮中途仅调整了调度方式。

测试用自编案例验证2个和4个写入阶段确实重叠、读取并发为1、互不误删集合、全部回答后的评分屏障、失败后的停止入队、既有回答和失败逐字节保留，以及当前read结果接管时不触发模型重答。相关29项检查通过。
