# memsys 检索与分块重构实施计划

更新日期：2026 年 10 月 10 日。当前状态：已采用普通角色分块＋本地 BGE 重排。父子分块及语义边界实验已从运行代码、配置和新库结构移除，冻结源码及评测证据保留。查询规划和复核继续沿用已验证的默认行为。实施结果见 [重构评估](rag-refactor-assessment.md)。

本轮以本地 BGE 重排、父子分块和长文本语义边界为主线，减少答题阶段的云端调用，同时改善问答关联、跨段指代与时间上下文的召回。实施顺序为：冻结基线 → 接入 BGE → 改造分块与索引 → 验证语义边界 → 评测 → 切换默认配置。查询分析和答案复核的按需策略另做消融，避免多项变化同时发生而无法判断收益来源。

## 本轮执行结果

- A 冻结复测 32/48；B1 旧分块加受限 BGE 重排为 39/48，答题云端 token 减少 31.53%；C 父子分块加 BGE 为 33/48，p95 162.68 秒，超过预设 130.59 秒门槛。
- 扩展环境 342 项测试全部通过；9 个本地工程阶段、真实 tokenizer 并发预检、语义边界缓存机制及实际磁盘中断/回滚演练通过。只改分块的配对迁移没有云端事实重抽取。
- 用户已授权采用 B1 路径。本机正式配置为固定 revision 的 BGE、MPS/float32、batch 4、严格失败；跨设备默认 CPU。父子分块与语义边界只保留历史实验记录，当前代码不再启用。按需查询与复核没有独立模型质量验收，不推进其默认切换，未回放全量 500 题。
- 本轮两组都是已使用回归样本，同模型 judge 和服务变化限制结论。不能把观察到的 B1 净改善外推为通用准确率提升，也不能将 token 比例当成货币费用。

以下保留原定实施设计与验收要求作为历史记录；父子分块和语义边界章节不是当前执行指令，复现须使用 `runs/rag-refactor-v17/frozen-sources`。当前启用方式以 README 和配置为准。

## 技术选型与范围

| 环节 | 最新方案 | 状态 |
| --- | --- | --- |
| 云端模型接入 | 保留 OpenCode Go 的多协议适配和候选池；GPT、Claude 等海外模型优先，再到 DeepSeek 等国产模型；额度或可用性失败时自动切换 | 已接入，沿用 |
| 向量召回 | 保留本地 `bge-m3`，与关键词检索融合 | 已有，沿用 |
| 重排 | 本地 `BAAI/bge-reranker-v2-m3`，常规检索使用 BGE | 已采用；LLM 仅作历史对照，融合排名作离线与明确降级 |
| 分块 | 普通角色连续分块，保留原始字符区间 | 沿用；父子运行分支退役，旧实验库可显式 reindex |
| 语义边界 | 不执行 | 实验未获得稳定质量收益，代码及缓存结构退役 |
| 查询分析 | 原问题直接混合检索作为低成本路径，复杂问题按需调用规划模型 | 开关已实现，默认仍保留原行为；质量对照在基础方案通过后开展 |
| 答案复核 | 程序检查继续执行；将模型复核策略与跨页语义处理拆开，再比较按需复核 | 已拆分及机制验证，默认仍保留原行为；按需复核待独立对照 |
| 评测 judge | 固定 LLM judge，仅在评测时对照参考答案；程序检查单独记录 | 沿用同口径评测 |

BGE 重排输入是“问题与候选文本”，输出相关性分数；它与 `bge-m3` 的向量相似度召回承担不同职责。具体实现采用官方支持的 Transformers 接口，固定模型及 tokenizer 版本。[BGE 官方模型说明](https://huggingface.co/BAAI/bge-reranker-v2-m3)

## 当前基线与主要问题

当前原文向量按 User、Assistant 分开切块，保留原始字符区间，没有重叠。默认 `embed_chunk_tokens=384` 随全局 `budget_mode=utf8` 计数，实际限制是 UTF-8 字节，并非 BGE tokenizer 的 384 token。检索已经能从命中子块恢复一轮原文，但尚未建立连续主题父块及跨轮依赖关系。

常规读取包含查询分析、混合召回、LLM 重排、答案生成和模型复核。求和、计数、完整列表等问题还会分页取证与跨页合并，因此不能把所有问题都视为固定四次调用。

重构前已有评测记录为固定组 **25/34，73.5%**，原留出组 **12/14，85.7%**；扩展环境回归 322 项通过。这些成绩来自此前的语义修复，不是 BGE 或新分块的收益。两组现在均属于已使用样本，下一轮不能把原 14 题再次称为未见留出集，也不能据此外推全量 500 题准确率。[原有评测记录](../runs/semantic-repair-v16/assessment.md)

本轮重点覆盖原问答分离、边界处条件缺失、基值与增量分离、跨轮指代和长原文主题混合。对象归属、事件去重、累计状态理解等错误还涉及推理与语义裁决，分块和重排不能单独保证修复。

## 改造后的答题流程

1. 接收原问题，提取关键词；查询分析策略决定是否生成补充查询、时间范围或完整检索要求。
2. 对问题生成 `bge-m3` 向量；同时在子块和结构化事实中执行向量召回与关键词召回。
3. 融合排名，把子块映射回父块，合并重叠区间，恢复相关问答、角色、日期及必要的邻近上下文。
4. 用本地 BGE 对事实和父块的相关窗口重排，再按回答预算选择证据。
5. 由云端 LLM 根据证据生成答案。需要完整统计的问题继续分页取证、语义合并及程序计算。
6. 程序检查引用、单位、计算和日期凭据；模型复核按独立策略执行。记录实际模型、证据、检查结果、云端用量和本地耗时。

对于需要完整证据的题型，BGE 调整阅读顺序，不缩减完整候选集合。最终可回答性依赖覆盖与证据核验，不能由重排分数代替。

## 阶段一 冻结基线与建立观测

保存当前源码、提示词、配置、模型身份、样本及原始历史的指纹。以独立数据库副本做实验，保留原文、事实版本链和生命周期状态。

补齐读取追踪：召回的子块、来源区间、父块扩展原因、融合排名、重排输入窗口、重排分数、最终证据、预算单位。用量按写入、查询、重排、分页取证、回答、复核、judge 分开统计；本地推理记录设备、批大小、耗时与峰值内存。

交付物为冻结清单、可复用记忆库副本和同口径基线报告。历史成绩作为参考；正式对照以本轮冻结基线为准。

## 阶段二 接入本地 BGE 重排

先在现有分块上替换重排，隔离验证这一项变化。新增统一重排接口，支持 `llm`、`bge`、`fusion` 三种后端，便于对照及回滚。`fusion` 表示保持混合检索排名。

采用可选依赖、惰性加载和进程内复用，固定模型 revision 与 tokenizer revision。在当前 Apple M4、16 GB 环境测试 MPS 与 CPU；由测量结果选择设备、精度和批大小。对并发调用设定共享推理队列，避免重复加载权重或多批推理导致内存峰值失控。

重排对象包括结构化事实和原文候选。事实携带对象、日期及版本状态；原文窗口保留角色和对应问题，避免助手回答脱离提问。长文本按 reranker 自身 tokenizer 的问题与文本配对预算生成多个窗口，再以确定性规则汇总候选分数，禁止只截取开头而丢掉命中位置。分数用于排序，不解释为答案正确率。

加载或推理失败时记录原因；运行模式可退回融合排名，严格评测模式则标记该实验失败，不能静默退回 LLM 并算作 BGE 成功。

交付物为本地后端、配置和追踪字段、设备资源报告，以及“旧分块加 BGE”的对照结果。

## 阶段三 建立父子分块与真实 token 上限

### 父块组织

短对话以一轮完整问答为父块。长轮次按连续主题划分父块，每个父块保存组成它的原文片段和顺序。跨轮上下文先采用有界邻近扩展；明确延续同一话题时再组合相邻轮次，且保留每轮独立的日期和来源。

不同用户、不同会话以及不同历史状态不合并成一个无日期区别的事实。会话记录日期与事件发生日期分别保留。父块中的助手建议与用户已确认事实保持角色区别。

### 子块切分

先识别段落、句子、列表及代码结构，再在 embedding 模型的真实 token 上限内组合；超长句或结构单元才进一步切分。角色、必要上下文前缀和特殊 token 一并计入上限。

首轮对照参数为子块上限 256 或 384 个 embedding token、重叠目标 32 或 64 token；重叠优先保留完整句子。这些是实验起点，最终默认值由召回与资源结果确定。单句超过硬上限时采用可追溯的细分，而非丢弃。

原文使用字符区间作为真源，token 计数只用于限长。重叠子块的区间并集必须完整覆盖父块原文，每个片段都能逐字回读；角色和上下文前缀属于检索元数据，不能伪装成原文引用。

embedding、reranker、回答上下文各自使用独立计数约定。回答预算继续遵守现有可验证计数方式，并明确单位；本次不把字节预算直接改名为聊天模型 token。

### 索引与上下文恢复

新增父块、来源片段和子块映射，扩展现有 `episode_chunks` 的元数据；建立子块全文索引，保留结构化事实索引与旧数据读取兼容。向量与关键词先召回子块，再按父块去重，父块不因子块多而获得重复加分。

恢复上下文优先采用完整短问答；长父块采用命中句段及必要邻近片段，按原文顺序呈现并标明省略。对基值与增量、指代与先行词的依赖加入定向回归，不以无边界扩展整段历史来补救。

父块扩展和事实来源展开均遵守遗忘、禁止读取及归档规则。求和、计数、完整列表、历史比较继续保留既有覆盖检查和分页路径，不被普通检索的 Top-K 限制截断。

交付物为可追溯父子索引、子块全文检索、上下文恢复逻辑及“父子分块加 BGE”的对照结果。

## 阶段四 增加长文本语义边界

只对超过结构切分阈值、仍包含多个主题的父块执行语义边界检测。用本地 `bge-m3` 比较相邻句段的向量变化，结合段落、列表、角色和日期约束确定边界；不把远处相似句子聚成脱离原文顺序的父块。

加入最小块长度、最大块长度与边界稳定规则，避免主题频繁切换产生大量碎块。写入时缓存句段向量，增量更新优先重算变化区间及其邻域。以中文、英文、列表、代码、相对日期和基值依赖样例验证边界行为。

语义边界需要单独比较召回、答案及索引开销。相关研究没有发现其在不同检索和 RAG 任务上稳定优于固定切分，因此采用选择性启用，并以本项目结果决定默认策略。[语义分块研究](https://aclanthology.org/2025.findings-naacl.114/)

交付物为可开关的语义边界策略、缓存和“父子分块加语义边界”的对照结果。

## 阶段五 迁移索引并验证回滚

将事实抽取指纹、检索索引指纹、读取配置指纹分开。索引指纹包含 embedding 模型与 revision、tokenizer、分块策略、参数、元数据格式和索引代码版本。重排模型及策略进入读取指纹。

仅修改分块或重排时，复用原始历史和既有事实，重建需要变化的检索索引；不重新调用抽取模型。改变事实抽取、更新裁决或实际影响事实写入的 embedding 行为时，正式端到端对照重新建库。

在独立副本或临时索引代中构建新索引，校验来源区间、向量数量、维度、全文索引、生命周期过滤和事实版本链后，事务切换索引版本。失败、进程中断或指纹不符时保留旧索引可读状态。保留旧索引与配置用于回滚；兼容旧库，但禁止混用不同分块或向量版本。

交付物为迁移入口、索引清单、幂等与中断恢复验证，以及一次实际回滚演练。

## 阶段六 比较查询分析与复核策略

在 BGE 和分块方案通过后，再比较查询与复核，以免把其影响归因于 BGE。

查询分析初步策略：单一事实、人物、偏好查找直接使用原问题和关键词；跨会话依赖、时间条件、最新与历史比较、完整聚合等问题允许规划模型增强检索。触发器优先使用可审计规则及检索信号；低置信度进入复杂路径，避免节省一次调用却漏掉完整检索要求。

答案复核新增独立策略 `always`、`on_risk`、`off`。程序对引用、计算、日期及单位的检查继续执行；数值或时间操作、证据矛盾、跨页汇总、条件归属不明确时，`on_risk` 调用模型复核。复核不能补造未提供的证据。

现有 `semantic_validation` 同时控制操作语义、跨页事件合并和回答复核，先拆分这些职责，保持跨页处理的原有行为。正式验证前保留 `always`；按需策略通过独立对照后才调整默认值。

通过后，简单查值题的目标路径为本地召回与重排加一次云端答案生成；复杂题仍允许额外规划、取证及复核调用。

## 评测设计

| 版本 | 唯一新增变化 | 要回答的问题 |
| --- | --- | --- |
| A | 本轮冻结基线 | 当前行为与真实用量是多少 |
| B | 旧分块加 BGE | 单独替换重排的准确率、用量和本地开销 |
| C | B 加父子句段分块 | 上下文恢复是否减少证据遗漏 |
| D | C 加选择性语义边界 | 长文本收益是否覆盖额外索引开销 |
| E | 选定 B 至 D 方案加按需查询 | 少调查询模型是否导致复杂问题漏检 |
| F | E 加按需答案复核 | 简单题省调用后是否增加未发现错误 |

先用自拟机制样例和针对性回归验证，再用固定 34 题及原 14 题做配对比较，保持题目、时钟、事实库口径、预算、回答模型和 judge 一致。检索隔离实验复制同一事实库，仅重建各自索引；需要验证写入行为变化时另做同版本完整写入实验。只对有必要的候选版本执行后续实验，不默认回放全部 500 题。

评测期间关闭模型自动切换，固定回答与 judge 的模型标识及参数，保存响应报告的实际模型身份；提供方未公开底层 revision 时，在冻结清单中注明。额度失败记录原始失败，待同模型恢复后续跑。正常运行保留海外优先的自动切换，并通过单独冒烟测试验证，不混入质量对照。

参考答案只在生成完成后的 judge 步骤使用。judge 是 LLM；程序核验与离线启发式评分不能替代其标签。记录实际 judge 身份；同模型复核及评分不构成独立正确性证明。对回退题人工检查证据与错误原因，保留原 judge 标签。

报告逐题正确与错误变化、各题型结果、证据召回与覆盖、拒答、迁移异常、云端调用和输入输出 token、本地索引与重排耗时、端到端延迟 p50/p95、峰值内存。只有完整配置价格时计算货币费用；价格未知不记为零费用。

## 验收标准

- 原文来源可逐字回读；子块区间并集无缺失，重叠不导致重复统计；token 上限、角色、日期、对象及历史版本检查全部通过。
- 遗忘或禁止读取的内容不能经子块、父块扩展、全文检索、事实来源展开或重建索引重新出现。归档按既有规则处理。
- 完整聚合不因 BGE 排序或 Top-K 筛选丢失候选；超出完整覆盖预算时明确报告限制。
- 迁移幂等，中断恢复和回滚通过；仅变更检索分块不触发云端事实重抽取。
- 新增有行为价值的定向回归与现有完整回归通过，再执行模型评测。
- 与本轮冻结基线配对比较，默认配置的净正确题数不下降；每道原正确题回退均审查并修复或说明接受理由。固定 34 题中一题约为 2.94 个百分点，不以小样本承诺稳定提升比例。
- BGE 替换后的答题阶段云端 token 实测下降；同时报告本地开销，设备资源及 p95 延迟未超出首轮基线测量后制定的可接受范围。
- 追踪能解释实际重排后端、来源选择、计数单位、复核触发、模型切换与任何降级。

## 收益估算与目标

历史 48 题用量按“其他请求、证据、重试和缓存行为不变”做算术估计如下。token 比例是输入与输出数量直接相加，不是账单金额。[历史用量推算](../runs/bge-reranker-estimate.json)

| 变化 | 答题阶段云端 token 减少 | 含写入与 judge 的云端 token 减少 |
| --- | ---: | ---: |
| 仅以本地 BGE 替代 LLM 重排 | 约 23.53% | 约 5.62% |
| 再完全去掉查询模型调用 | 约 30.11% | 约 7.19% |

按需查询仍会在复杂题上调用模型，其实际减少量不能直接采用“完全去掉查询”的估计。新分块可能改变候选、证据长度和分页次数，正式收益以 B 至 F 的实际结果为准；本地推理也会占用设备资源。

准确率目标首先是保持基线，再改善问答关联和依赖上下文题，不预设提升百分点。只有通过必要配对对照的候选才进入默认切换，之后再决定是否启用按需查询和复核。本轮 B1 的观察收益与 C 的失败结果见重构评估，D/E/F 不因开关已经实现就被视为验收通过。
