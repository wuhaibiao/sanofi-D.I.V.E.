# 记忆读取可靠性修复与构建验收

2026年10月11日的修复已完成最新计划第一阶段的本地交付：读取步骤共用重试和时间预算，必需步骤的服务故障保留为未完成状态，评测支持限时和取消。构建包已通过隔离安装验证。真实接口验证因 OpenCode 免费层的接入限制停止，尚未进入40题验收，也没有新版正确率或性能成绩。

## 修复内容

一次 `respond()` 的查询规划、远端向量检索、回答、取证、计算修复和来源复核共用同一份读取预算。每次远端调用最多一次额外网络重试，整题最多两次额外网络重试，读取预算180秒；请求超时随剩余预算收紧。内置 HTTP 与 SDK 客户端在读取期间关闭自身的重复重试，写入保留独立策略。

明确的端点不可用、网关及连接故障、超时和取消会从必需的分页、计算和复核步骤继续传播。失败不会写入已完成答案。正常来源不足拒答仍是完成的读取；计算或语义判断失败保留既有审计原因。可选查询规划和重排的降级单独记录，整题超时和取消不能降级成继续生成。

每次网络尝试记录用途、状态和实际耗时；等待另记实际时间。成功答案和失败记录都保留重试预算及耗时。评测达到批次时间上限或连续两次同类服务故障时停止后续题目；已保存答案及评分保持原样，未完成覆盖写入 `execution.json`。

HTTP 响应按块读取并收紧套接字超时，避免持续发送少量数据延长读取期限。取消会停止等待和后续请求；已发出的同步请求依靠剩余超时退出。第三方注入的同步适配器必须每次调用仅执行一次远端尝试，并自行遵守超时。命令监督器提供进程级限时及取消，终止评测进程组并保存退出原因；终止后最多等待5秒清理，再强制结束。

## 免费模型配置与接入限制

已将用户指定的七个免费型号列为优先候选。协议、规范 ID 和零价格说明采用 [OpenCode Zen 官方目录](https://opencode.ai/docs/zen/)。Muse Spark 使用 Responses，其余六个使用 Chat Completions；Zen 免费型号使用 `/zen/v1`。

本次实际 Zen 目录确认 Ling 3.1、LongCat、MiMo、Muse Spark 和 Nemotron 3.5 Lightning。Ling 3.0 Flash Fin 与 Nemotron 3 Ultra 未在本次目录中出现，保留候选配置但不自动纳入切换链。Ling 3.0 和 Nemotron 3.5 的规范 API ID 使用小数点。

真实 API 调用返回 `403 FreeTierError`，原始错误为 `OpenCode's free tier can only be used from within OpenCode`。本机未找到 OpenCode CLI。直接 Python HTTP 接入尚不能使用该免费层，因此免费配置保存为[单独候选](../config.free-zen.example.json)，其当前切换链只包含目录确认的免费模型。默认配置继续使用此前的 Go Step 读取及评分、Go LongCat 写入、本地 BGE 检索；新增读取预算已生效。

下一步须先完成通过 OpenCode 正规客户端调用的适配或取得服务方支持的 API 接入方式，再验证3至5个受影响案例。模型或评分模型变化要单列；前置验证通过后才能按计划依次进入两组固定40题和新40题。写入源码指纹随客户端改动改变，现有严格缓存验证会要求重新写入；本轮没有绕过指纹校验或改写历史记忆库。
