# 入库优先的基础设施补跑

原轮结果不可覆盖。用户在原轮完成后要求“先处理没有入库的，全部入库了再答题”，因此增加独立协调器 `scripts/run_oracle500_recovery.py`。

补跑只按原回答记录的执行状态纳入全部失败项，不检查评分标签或按正确率挑题。原轮成功的回答和全部原始失败均封存并记录文件哈希；补跑与首遍评测分开报告。

执行顺序固定为：

1. 使用原冻结输入、模型、提示词和产品源码，新建各题隔离集合。4个worker仅负责入库。
2. 每题最多3次有记录的补入库尝试。原生写入器跳过补跑中已经完成的源会话，并对未完成的开放会话使用原有消息幂等键。非开放的失败会话阻塞，避免重复历史。每次尝试的请求、响应、用量和错误均独立保留。
3. 所有题的全部源会话都完成，且逐题审计原文向量和分块向量均为0，才能通过全局入库门槛。任一题未完成时，全批次禁止答题，暂存集合保留供排查。
4. 入库门槛封印后，读取并发1，每题执行一次答题。答题后只删除本题集合并验证；其他题的待答集合继续保留。
5. 全部补跑回答固定并清理后，独立进程、独立会话统一评分。原轮成功回答直接沿用，不再次调用答题模型或评分模型。
6. 校验原轮保护文件、补跑输入、阶段时间顺序、回答哈希、集合清理和官方原始题号，生成补跑报告及 `composite500/` 合成结果。缺少有效回答时只生成部分提交。

进程死亡、账户/额度问题、冻结检查、原文向量审计或清理失败时停止，不自动重启。失败重试达到预算也不得越过入库门槛。预期的暂存集合不属于泄漏，不能在入库阶段清除。

合成成绩明确披露基础设施重试与历史暴露，不替代原轮首遍成绩，不宣称新的盲测。Qwen同模型独立阶段评分属于自测，正式项目组复评另算。
