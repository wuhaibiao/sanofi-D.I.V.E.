拒答变体与基础题分别执行，不按基础题号去重，不按历史得分、问题、参考答案或长度筛选。

1. 冻结当前部署实际使用的配置、产品源码、提示词、评测工具、依赖和数据哈希。显式使用部署的本地 BGE-M3，避免缺失 embedding 配置时意外回退为哈希向量。
2. 机械生成写入、答题和评分三套白名单文件。历史按日期排序；写入阶段不包含评测问题、答案和证据标记；答题阶段没有参考答案或历史正文；评分完成前不分析答案表现。
3. 每题使用独立 Qdrant 集合前缀和 namespace，从空库写入该题全部历史。记录写入事实及存储审计，再由当前事实召回路径生成回答。
4. 保存实际请求、原始提供方响应、适配器正文、finish_reason、usage、检索轨迹、延迟与错误。既定传输重试和输出扩容按冻结产品逻辑运行；不因判分重答。
5. 删除本题所属集合并验证为空；核验既有集合保留，再启动下一题。清理失败、进程异常或账户/额度错误立即停止，原始结果留档；不自动重跑已启动的评测。
6. 所有题的答题及清理完成后，才以独立进程和独立服务商会话逐题评分。沿用当前配置模型和官方语义评分提示词；属于自测，项目组指定统一裁判的分数另行报告。
7. 生成 `metrics.json`、`report.md`。只有全部500题都有有效实际回答时才生成 `hypotheses.jsonl`，每行仅保留原始 `question_id` 与 `hypothesis`；否则仅输出 `hypotheses.partial.jsonl`。未完成时不声称全量准确率。

运行目录为 `runs/oracle500-<date>-<time>/`。每题证据保存在 `questions/0001` 等目录；全量输入和配置只在本机私有运行目录，不把凭据提交仓库。数据库逐题清理，写入结果与审计仍保留。

报告包含总体、六题型、拒答、Task-averaged、交付与评分失败、分用途 token/费用/耗时、完整检索路径延迟、代码/模型/数据来源。单价未知时费用写未知；UTF-8字节预算与模型实际token分别解释。检索路径耗时含查询向量、检索、BGE和上下文组装，不能当作纯向量查询延迟。

历史公开题暴露仅作报告说明，本轮通过空库、输入白名单、阶段/会话隔离防止运行时混入旧记忆或标准答案。Oracle结果不能外推完整长历史干扰条件；自测裁判与回答采用同模型时明确披露。

入口依次为 `scripts/run_oracle500.py prepare --out <新目录>`、`scripts/run_oracle500.py preflight --out <同目录>`、`scripts/run_oracle500.py run --out <同目录>`。预检只使用自编输入；当前冻结配置的真实预检未通过时不能启动评测。
默认配置来自本机部署 runtime 中的实际 config_path。长任务以独立进程运行，保存 PID、进度和日志，并用系统 caffeinate 防止运行时空闲休眠。
