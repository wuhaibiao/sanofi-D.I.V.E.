# 先评分现有入库，再分批评测剩余题目

用户在入库优先补跑因Qdrant文件句柄上限退出后，要求“先评分，评分完再重新评测剩下的题目”。新调度器是独立修订 `scripts/run_oracle500_batches.py`，不修改原轮或旧补跑的源码、提示词、配置、输入、封印、状态与失败记录。

首先机械核对旧补跑的完成记录，首批纳入全部写入完成项。已审计的入库直接复用；写入完成但未审计的项补审计，不重复抽取。每题仍使用原隔离集合与命名空间。

首批全部写入并审计通过后，各题依次读取事实并答题，完成后删除本题集合并验证其他暂存库与个人集合保留。首批回答全部固定且清理完成后，独立进程、独立会话统一判分。首批评分未完成时禁止后续题入库。

剩余项按官方原始顺序、每批最多8题评测。每批都遵循“全批入库审计—答题—清理—独立评分”；批次顺序在任何新评分之前冻结。不能根据逐题结果改动产品、模型、提示词、输入或后续批次。

沿用累计入库尝试次数，包含旧补跑中已经启动但子进程失败的尝试。已完成源会话由持久标记跳过，未完成的开放会话使用原消息幂等键。每题至多3次累计尝试，不自动重置预算。非开放的失败会话、预算耗尽、账户问题、冻结或清理校验失败、未评分标签都阻塞后续批次。

原轮365份有效回答不重答、不重评分。最终报告明确区分原轮首遍成绩与重试后的合成成绩；每批指标只使用本批分母，全量未完成时不得把已完成子集准确率称为500题成绩。未达到500份有效实际回答时，只生成部分提交。所有费用零兼容字段仍按未知成本解释。
