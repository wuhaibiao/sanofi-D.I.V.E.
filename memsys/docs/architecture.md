# memsys 架构

2026-10-27 已部署逐条抽取隔离与建议任务组织：坏条目不再使完整数组中的有效事实整批丢弃；来源与内容缺口单独保留，诊断原始响应不进入回答检索。建议在同一次生成内选择适用目标与限制，任务元数据及信封标记错误都只影响审计。201项相关检查及16次自编真实调用的交付和内容复核通过；未重跑原20题，不作为整体准确率证明。已知旧断言、初次验证失败和部署数据核验见[修复报告](../runs/task-context-isolation-repair-20261027/report.md)。

2026-10-26 原子事实与用户上下文传递修补：同次抽取按独立陈述保留具体属性、明确目标和限制；建议类读取在选取及最终展示时均优先已召回的用户上下文，按同一格式计算预算，每条只展示一次。宿主第一次回答获得相应记忆使用规则。覆盖声明明确只核验源关联，不证明内容完整性；证据审计仍仅作诊断。模型调用边界及存储 schema 不变。详见[实现与验证边界](memory-fidelity-repair.md)。

2026-10-25 已撤回列式抽取，恢复命名字段的事实对象；列式转换模块已删除，存储 schema 不变。当前本机抽取专用配置为32,768输出token、360秒超时，单批仍只抽取一次；截断或损坏响应整批失败并保留原文和水位。覆盖补取分别处理字节与条数；超过全库枚举上限时继续有界检索，但不能声称完整。BGE 同请求内相同配对输入共用推理，来源窗口独立保留；请求编码缓存正常或异常结束后清理，权重继续常驻。验证及部署边界见[恢复报告](../runs/object-extraction-repair-20261025/report.md)。

当前主线是可接入不同 Agent 的记忆服务。Qdrant 是唯一在线主存储；SQLite 仅在显式旧库迁移工具中只读打开。最终答案由宿主 Agent 生成，记忆层不统一审查、评分或改写答案。

当前实际部署切换到本机 macOS 原生进程：`127.0.0.1:8848` 记忆 API → `127.0.0.1:6333` Qdrant、`127.0.0.1:11434/v1` BGE-M3；BGE 重排在记忆服务进程内运行。模型及访问令牌管理见 [本机部署](local-deployment.md)。抽取 LLM 沿用既有外部 API，不依赖用户的云服务器。

主流程参考 [Mem0 当前新增写入架构](https://docs.mem0.ai/core-concepts/memory-operations/add)：相关旧记忆作为上下文，LLM 单次抽取，程序按完整事实字段去重后新增；检索返回记忆，宿主 Agent 生成答案。已移除独立的新旧事实裁决、裁决修复及自动取代。没有引入 Mem0 作为运行依赖；Qdrant、完整原文与来源接口沿用既定部署。

当前检查包括关键存储与接口测试，以及用户授权的LongMemEval小样本修复回归；不自动扩展到正式全量验收或可选消融实验。

## 模块与功能

| 模块 | 功能 |
|---|---|
| `core.py` | 会话、记忆读写、版本历史、遗忘、分页、补抽与索引维护的统一入口 |
| `store.py` | Qdrant 中的原文、事实、来源、版本、提交记录、游标与持久任务 |
| `relational_memory.py` | 实体标识、显式别名来源验证、事实关系索引、时间／遗忘约束及两跳扩展 |
| `working_memory.py` | 完整轮上下文窗口、独立预算及淘汰前整理水位检查 |
| `qdrant.py` | 服务器 REST 调用、租户过滤、条件写入、集合和 payload 索引 |
| `write.py` | 将原始消息切成轮次，抽取原子事实，生成向量与角色分段 |
| `extraction_protocol.py` | 逐条隔离无效事实协议；仅凭唯一的同角色字面引文修复来源表示 |
| `task_context.py` | 将建议所用的已选事实按明确任务、目标、限制和资源分组 |
| `update.py` | 确定性的完整事实字段去重与新增，不调用模型 |
| `fact_content.py` | 全值展示、字段身份及索引内容格式指纹 |
| `structure_memory.py` | 助手编号列表和 Markdown 表格的紧凑字面结构解析 |
| `memory_compaction.py` | 同轮结构覆盖证明、完整值展示共享、显式事件状态格式兼容 |
| `read.py` | 默认直接进行向量与词法召回、融合、BGE 重排及预算选择 |
| `memory_pages.py` | 按预算返回完整候选证据的分页；不生成答案或计算结论 |
| `lifecycle.py` | 按重要性、时间和使用频率归档；来源及版本链接保留 |
| `maintenance.py` | 补抽计划、备份、清理、完整性检查与离线压缩 |
| `migrate.py` | 显式只读导入旧 SQLite 的原文、当前向量、来源与版本关系 |
| `serve.py` | 记忆 HTTP 接口、宿主模型代理、访问鉴权、并行持久后台任务 |
| `client.py` | Agent 通过本机 HTTP 接口调用记忆服务的 Python 客户端 |
| `webchat.py` / `web/` | 本机聊天网页与独立宿主 Agent，对话历史保存在 Qdrant，生成一次最终回答 |
| `remote_rerank.py` / `rerank_server.py` | 远程重排客户端及独立 BGE 服务 |
| `agent_adapter.py` | 示例宿主 Agent，只进行一次最终生成；没有答案复查 |

`MemorySystem.respond()` 仅为旧调用方转发到示例 Agent 的兼容入口。新接入使用 `recall()`、`recall_pages()` 或 HTTP；核心不生成最终答案。历史的答案复查及评测模块不在这条主流程中，旧评测脚本和旧 SQLite 测试尚未迁移或执行。

本机首页提供聊天界面。网页宿主 Agent 每次生成前都从记忆层检索上下文，然后调用既有回答模型，历史、消息重试记录和来源参考保存在 Qdrant 的 `web_conversation` / `web_request` 数据记录中，不引入第二种数据库。新建对话、切换到侧栏其他对话或达到现有整理阈值后，将消息交给相同后台抽取任务。其他对话原文写入引发的发布冲突只重试短事务，事实上下文或当前整理水位变动时则重新准备抽取。网页不做答案审查，也不为标题另调用 LLM；标题由首条消息确定。等待状态用 SSE 返回，生成完成后显示完整回答。

## 写入与状态

V7 将实体与关系加入既有单次抽取协议，不新增图数据库或额外抽取调用。实体类型及关系描述随相关旧事实进入抽取上下文，帮助后续会话保持身份一致；上下文仍不能成为新事实的证据。程序验证事实引文和命名端点；实体别名另验证同轮同角色中显式的命名声明，并记录独立来源 span。类型／身份冲突和别名歧义保留，不做模糊合并；通用事件名不能成为发生标识。

关系 payload 保存实体端点、关系类型、有效期、记录时间、业务状态、限定条件、来源及事实 ID。`entity` / `relation` 与事实和整理水位在同一个应用提交协议内发布，不进入事实稠密／词法索引。关系状态不等于事实生命周期状态，记录时间不等于发生时间。不自动改写旧事实；首次读取时召回显式结束／取消证据，并阻止沿同一范围下已明确结束的旧关系继续扩展。旧格式只索引明确主体或 object_key 的关联，不把这些关联宣称为所有权、雇佣或参与关系。

默认最多2跳、32节点、96关系及32关联候选；不遍历全局 user/assistant 节点。向量及词法候选与关联候选按事实 ID 合并。每条关系的事实必须满足最新租户版本、生命周期和时间检查；遗忘的关系不能作为桥梁。实体同名歧义进入读取提示。所有上限及截断状态记录在 trace；这些覆盖声明是程序查询范围的覆盖，不能证明抽取或语义相关性完整。

HTTP `/memsys/recall` 与 Python 客户端返回 `relations` 和 `coverage_supplement` 的有界诊断信息。外部宿主可通过 `coverage_budget` 传入扣除自己框架、当前问题和近期窗口后的事实预算，控制首次回答前补入的事实；核心仍受服务总输入预算及事实条数上限约束，不生成答案。

WebChat 与示例 Agent 在首次回答前准备工作窗口，按完整轮及独立预算保留近期消息。淘汰轮次尚未整理时同步整理至对应的完整轮边界；没有抽取服务或整理失败则保留待处理消息并报错。不会逐条弹出消息而留下孤立助手回复，也不会静默截短当前问题。总输入预算先为宿主框架及近期窗口留出空间，再用于事实。汇总候选已有遗漏时复用同一次搜索和重排结果，在剩余预算内补入最多128条事实；仍不足时明确只提供已知子集。首次最终生成触顶时可扩大输出预算，对相同完整输入最多额外生成两次，不调用评分器或答案复查模型。

`chat_window_turns=12` 表示完整轮上限，本机窗口独立预算为24,000 UTF-8字节，完整回答输入预算为131,072字节；实际可保留轮数随消息长度变化。回答初始输出8192 token，上限32768；抽取初始输出65536 token，上限131072，推理预算由模型的 `output_token_headroom` 另行预留。每个不完整草稿只记入调用审计与用量，不成为历史答案或已发布事实。上限耗尽后保留原文和原整理水位。旧数据关系索引升级仅读取既有事实，不从私人历史重新抽取。

WebChat 直接生成并交付用户可见正文。回答不要求证据清单、计算元数据、内部事实ID或审计JSON信封，也不执行回答证据绑定、对象身份或算式复核。对缺少前提的结论，提示词要求模型保留不确定性；这是生成指令，不是程序对答案正确性的证明。请求记录仅保留交付状态及输出扩容尝试，用量账本记录真实调用。

本机BGE客户端配置每段4096 UTF-8字节，超长事实和查询完整分段编码，并按片段字节权重合成单位向量，返回顺序和原输入条数保持一致。事实本身不截短；既有私有记录不自动重抽或重建索引。分段策略写入模型清单。

1. Agent 打开会话，携带用户身份与外部会话 ID。服务将原始消息及时保存到 Qdrant。
2. 每条消息可以携带稳定的 `idempotency_key`。网络重试使用同一个键；相同键但正文不同会报错。
3. 会话结束或达到整理阈值后，创建持久任务。不同用户的任务可以并行。
4. 后台将消息整理为带角色、时间和顺序的轮次。显著性门控决定是否建立检索索引，原始消息仍保留。
5. 按整批新消息查询至多 10 条相关旧记忆，并带入同一会话最近 10 条已处理的安全消息；它们只提供上下文，不充当新事实的来源。不按字节预算截断对话或旧记忆。
6. 整批消息进入同一次抽取调用，输出主体、属性、完整值、事件时间、置信度及来源编号。列表、表格和序列以紧凑 JSON 保存命名值、表头、行列关系和步骤顺序。完整且可解析的事实数组逐条校验：无效条目被隔离，有效条目继续统一提交，报告明确标记协议不完整。缺失或不合法的轮次只在全部字面引文都能唯一匹配同批同角色原文时修复；单轮批次缺省轮次可直接绑定，显式的错误来源不能凭单轮条件猜测。结构覆盖提示只报告可观察的缺口，不声明语义完整。
   同批次再解析助手明确的编号列表和 Markdown 表格，补充模型可能漏掉的字面结构。列表保留原编号、名称及不超过 240 UTF-8 字节的无标签短动作；标题后的解释不保留，较长无标签条目记录跳过位置。表格保留完整表头和单元格。解析器不使用问题、评分或标准答案，不处理普通段落、代码围栏及不明确的格式；完整来源片段只写入溯源记录。
   V6 在同一轮的助手模型事实已精确保留位置、名称/短动作或完整表格时省去重复回补，并将字面来源片段关联到原模型事实。覆盖不明确、行列或顺序不同、源列表标记有遗漏、角色不同或轮次不同均不省略。明确事件状态可以位于语义字段、顶层字段或事件JSON值；格式兼容只复制枚举状态，不读取正文猜测。冲突的明确状态会隔离该条事实，保留其他有效条目。
7. Embedding 模型为事实正文及必要的完整值、原文角色分段生成稠密向量；词法索引使用相同事实内容。原文向量仅供显式诊断模式使用。BGE-M3 可以通过远程 OpenAI 兼容接口使用。
8. 提交时先用摘要文本哈希定位候选，再核对完整值、主体、属性、类型、时间及语义条件。字段一致的重复记忆关联本次来源，不改变旧值、状态或置信度；同一句摘要但关系或值不同的事实分别新增。提交前核对事实版本及会话处理位置；并发变化会使提交失败并重试。
   对没有事件日期和发生标识的事件，完整描述相同也不能证明是同一次发生；不同会话或来源轮次分别保留。
9. 新事实、来源、向量及处理游标一起进入应用提交协议。没有抽取模型时，原文先建索引并保留补抽记录；补抽按会话整批处理，同样只做一次抽取和程序去重。

正常写入每个非空批次调用生成式 LLM 一次；不按固定长度切块，也不因格式错误拆小重抽。输出触顶只按既定上限扩大预算重生成完整输出。拒绝、预算耗尽后仍不完整、损坏 JSON 或缺少事实数组时，原文与处理位置保留，整批明确失败，不从残缺草稿抢救事实。完整数组内的条目异常采用上述隔离策略，即使全部条目被隔离也记录处理完成及信息缺口，不宣称内容已完整记住。短暂网络故障及并发冲突仍按持久任务机制重试。Embedding 原文角色分段只用于向量索引，不增加生成式 LLM 调用。默认检索不调用生成式 LLM，最终回答由宿主产生。

异常、无损来源修复及输出扩容时，完整抽取请求、每次原始响应和条目原因保存为 `extraction_diagnostic`。它与原文均在现有租户权限下保存，不进入事实或原文检索索引。部分或失败批次另累计 `extraction_health`，事实模式召回只读取这个紧凑状态并提示信息缺口，不读取诊断正文作答案依据。状态与 `WriteReport.extract_protocol_complete` 反映协议完整性；语义覆盖仍未验证。隔离条目不会自动重新抽取，也不会因后续成功写入自动清除未解决提示。

建议请求根据适用的用户目标与限制组织具体建议。抽取可选保存 `context_role` 与来源明确的 `task_key`；召回按任务分组展示已选事实，旧的无标签事实仍可用。分组不证明计划当前有效，模型仍须读取取消、完成、日期与不确定性；未选择的助手方案不等于用户承诺，多个目标没有明确优先级时须给条件分支或聚焦提问。模型不再提交目标ID清单或 `advice_task` 元数据，宿主不复查或改写答案。

回答请求不强制JSON模式，也不按业务字段名解析或拆出正文；用户要求JSON时按模型生成内容原样交付。宿主只检查生成是否完整结束、正文是否非空；输出触顶仅按既定上限重生成，拒绝和过滤不触发重答。历史评测中的回答信封与审计结果保留为旧版本记录。

`Writer.restore_structures()` 可显式从已保存的安全轮次回补上述结构事实，只调用 Embedding，不重新调用抽取模型。回补排除已遗忘和被屏蔽的轮次，提交前校验事实版本与历史指纹；重复执行不重复新增。这种回补验证需要与从全部历史重新抽取的端到端结果分开报告。

旧 `extract_chunk_tokens`、`extract_full_rounds`、`extract_assistant_chars`、`extract_context_tokens` 配置已退役，读取时告警后忽略。`memory_input_budget_tokens` 仅保留给可选查询规划、LLM 重排等功能，不限制记忆抽取；`extract_max_tokens` 为输出上限。

会话状态：`open → closing → closed`。`closing` 表示已收到结束请求，禁止继续追加；后台完成整理后转为 `closed`。如果结束请求与任务创建之间中断，后台根据 `closing` 状态恢复任务。

任务状态：`queued → running → completed`。暂时性失败进入 `retry → running`；输入超限、鉴权或参数错误、输出截断和格式错误进入 `failed`，后台 tick 和重启不自动重新调用模型。修正原因后，调用方可通过 `POST /memsys/retry` 或 `MemoryClient.retry_job(job_key)` 显式重试；状态接口返回失败原因。租约及续期使用独立 Qdrant 记录的条件写入，任务状态和重试时间持久化，超时租约可以重新认领。

事实状态：新建为 `current`，这里表示可参与检索，不保证它是某属性唯一的最新值。正常新增不会自动产生 `superseded` 或待确认冲突；内容变化保存为另一条记忆，排序与宿主结合时间和原文判断如何使用。旧库已有的版本链仍可查询，不做破坏性改写。低活跃记录可转为 `archived`；`confidence` 来自同一次抽取的陈述确定性，不作为最终答案评分。

轮次状态：可检索为 `active`，低显著性为 `skipped`，归档为 `archived`。主动遗忘可以使事实或轮次转为 `forgotten`；共享原文可能转为 `withheld`，防止从原文重新找回已遗忘信息。

## Qdrant 数据表示

| 集合 | 内容 |
|---|---|
| `<prefix>_records` | 无向量的原始消息、会话、事实数据、来源与版本、元数据、补抽记录及提交日志 |
| `<prefix>_dense_<dimension>` | 事实、轮次和原文分段的稠密向量；记录引用同一个已发布版本 |
| `<prefix>_lexical` | 相同记录的词法稀疏向量 |
| `<prefix>_jobs` | 独立的单记录任务状态与租约 |

所有集合都位于同一个 Qdrant 后端，不使用 SQLite 保存原文或关系。`namespace + user_id` 计算租户标识；读、写、检索、删除都限定租户。后台的命名空间用户目录扫描是专门的管理操作。

原文与会话可以没有向量；Qdrant 支持 payload 过滤和 scroll 读取。事实和轮次保留稳定的逻辑编号，向量点与提交版本使用 UUID。来源、会话、状态、主体、属性与版本字段建立 payload 索引。[官方数据说明](https://qdrant.tech/documentation/manage-data/points/)

词法召回使用共享分词器、词频、稳定哈希词项和 Qdrant IDF。中文使用相同分词规则。它是稀疏词法检索，不宣称与 SQLite FTS5/BM25 或 BGE-M3 的稀疏权重等价；哈希可能碰撞，词法只负责候选召回。

## 多记录提交

Qdrant 没有直接替代 SQL 多表事务的能力。当前实现使用不可变记录版本、操作日志及每个租户的发布头：

1. 写入 `prepared` 操作记录，并分批保存新的数据及索引版本。
2. 用条件写入将租户发布头从预期版本切换到新版本。该步骤是发布点。
3. 将操作标记为 `committed`。读取只接受已提交操作，或者当前发布头明确指向的操作。
4. 发布前的中断不会暴露部分数据。发布后但标记前的中断仍可读取；下一个提交先完成旧操作标记。
5. 两个写入同时使用旧发布头时，只有成功发布者可见，另一方收到 `WriteConflict` 并从新状态重试。

读取使用固定发布版本，按逻辑编号选择该版本之前最新的可见记录，再检查状态。不能先按 `current` 筛旧存储版本，否则可能把已经取代或遗忘的旧数据重新暴露。

依赖 Qdrant 1.16+ 的条件更新；客户端启动时检查版本，部署模板固定为已核对接口的 1.19.2。`wait=true` 和 `ordering=strong` 用于操作等待与顺序，不被当作原生多记录事务。[条件更新说明](https://qdrant.tech/documentation/manage-data/points/#conditional-updates)

这仍是应用协议：同一用户的短提交会竞争发布头；网络故障发生在发布点附近时，调用方应使用幂等消息 ID 重试。不同用户使用不同发布头。Qdrant 集群故障、跨副本恢复和多区域部署尚未验证。

## 读取

默认 `recall_mode="facts"`：问题 → 查询向量 → Qdrant 事实稠密/词法检索 → 排名融合 → 时间、状态、置信度加权 → 事实 BGE 重排 → 按预算返回事实。原文和角色分段不进入召回、来源扩展或重排；事实使用全部可用的记忆预算，同时仍受事实数量上限限制。`query_analysis=false`、`query_policy=off` 禁止额外的生成式查询规划。

事实输出统一包含描述和描述中缺失的完整值，日期、条件和状态单独标注。HTTP条目还返回原始句子、值、主体、属性、记忆类型和语义字段。重排使用同一完整内容，预算不足时移除整条事实，避免把值截成误导的半个关系。索引记录内容格式与源码指纹；旧的只含描述的事实向量不能直接复用，应重新生成向量。

V6 将明确的事件状态送入索引及重排，内容格式为3。上下文标明记忆类别；记录日期不当作事件日期，相对时间标明以记录日为锚，计划日期不描述成已发生。API与分页分别返回 `recorded_at`、`event_date` 和 `event_status`。旧数据缺少状态时维持未知，不重新抽取来填充。

同一次上下文中，只有结构值、角色、主体、属性、日期、状态、置信度和语义条件均一致，才用另一事实编号引用完整值；事实正文和各自编号仍逐条展示。每次预算调整后重新生成引用，避免锚点被移除后留下悬空引用。分页仍返回完整事实值，不跨页生成这种引用。该展示共享不减少既有BGE候选，也不合并存储中的事实。

建议操作在已经检索到的候选中优先选择用户相关事实，同组维持原相关性顺序；不增加新候选、查询LLM或原文。是否触发取决于当前意图识别，隐式建议表达的覆盖仍有限。普通查询保持既有排序策略。网页默认要求普通回答简洁完整；模型输出截断时返回失败，不将半条回复写成助手历史。

普通查询不拉回整个用户的向量矩阵。候选检索附带租户、记录类型、状态和发布版本过滤；返回后核对当前记录，排除旧索引版本。索引中保留的旧版本可能占用 ANN 候选，因此采用有界补取；正常 Top-K 查询不声明完整覆盖。

需要完整列表或总量时，默认只枚举该用户已发布的可检索事实，并使用 `recall_pages()`。候选数量限制只计算事实，原文数量不会挤占该上限。超过候选数量、分页数量或预算限制时返回覆盖不完整。完整枚举不保证事实抽取完整、库外事件完整，也不替宿主判断每条内容是否相关。

重排可选 `fusion`、`bge`、`remote` 或 `llm`。`remote` 将候选发往独立 BGE 服务，服务端进行模型加载、分词和角色窗口配对，客户端不需要本地 PyTorch。失败可按配置退回融合排序，并记录降级；严格模式则明确报错。

`recall()` 返回记忆文本、使用规则、编号、时间、状态、来源、置信度、版本关系及范围说明。宿主 Agent 把这些证据放进自身上下文并生成答案。记忆层不做答案复查、评分或自动改写。

原文保留用于审计、重建及明确查阅：事实来源仍返回 `E...` 编号，正文通过 `/memsys/sources` 取得。`recall_mode="facts_and_sources"` 显式启用旧的事实与原文混合召回，以及网页的待整理原文补充；此模式用于诊断，不能将其分数标为事实记忆能力。默认网页只保留当前对话最近 12 条消息的短期窗口，不补入其他会话或窗口外的待整理原文。抽取未完成、失败或遗漏的信息不会通过原文绕过事实记忆。

## 遗忘、迁移与维护

主动遗忘保留审计数据，但阻止其参与检索与补抽。只有明确的字面值与唯一原文证据区间通过检查时，才做细粒度替换；否则共享原文整体退出检索。近期对话也使用安全视图或屏蔽已整理前缀，避免绕过遗忘。

旧 SQLite 文件不会自动读取或改写。`migrate-sqlite` 只读打开指定源，导入到空租户，保留原始正文、来源、时间、事实编号、当前向量与安全视图，不调用模型、不重新计算向量。历史索引快照不导入；实验性的父子分段索引需要显式重建。迁移检查原文及关系完整性，源文件保持不变。

备份导出用户记录及任务，向量保存在数据载荷中，可据此重建索引。物理清理必须显式使用维护计划、备份和 `--offline`，并事先停止所有读写客户端；压缩删除旧存储版本，不删除合法的事实版本链。Qdrant 的实际磁盘回收由后台优化器完成，不承诺立即释放。

容量字段是已提交 payload 的估计值，排除未提交暂存、ANN 索引及服务器开销。本机配置关闭该应用估计额度；实际容量需结合 Qdrant 指标和磁盘监控。正常访问计数独立保存，不重写全部向量。

## 本机部署边界

记忆 API、Qdrant 和 Embedding 只监听 `127.0.0.1`，重排运行在记忆进程内。三个原生进程由登录启动项管理，数据、配置与访问令牌保存在用户的 `Library/Application Support/memsys/`。旧 Compose、Caddy 模板、服务器配置生成脚本及云端上传包已移除；服务器端旧实例清理方法见 [本机部署说明](local-deployment.md#清除旧云端部署)。

记忆接口、Embedding 与 Qdrant 均有独立鉴权。抽取 LLM 仍访问现有外部 API；本机部署不代表生成模型也在本机。健康与鉴权接口已检查，没有执行真实模型推理或评测。

HTTP 默认按服务器接收时间记录消息；历史导入保留原有时间。多时区事件时间策略尚未专门实现，Python 调用方可显式传入统一时间基准的 `at`。
