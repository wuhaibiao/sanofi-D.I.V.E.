# 检索与分块重构评估

评估日期：2026 年 10 月 10 日。对应 [最新实施计划](rag-refactor-plan.md)。核心重构和 A/B1/C 两组配对实验已完成。本地实验目录为 `runs/rag-refactor-v17`，其中的独立数据库副本、冻结源码、逐题答案、原始 judge 标签、用量和追踪均保留。

当前采用决策：用户已授权启用普通角色分块＋BGE 重排；本机配置采用 MPS/float32、batch 4、严格失败。父子分块及语义边界运行代码已退役，历史结果保持不变。当前启用与旧库兼容说明见 README，清理前源码与本轮验证记录保存在 `runs/bge-adoption-v18`。下文“已实现”和“切换前”描述对应 v17 实验状态。

采用后的验收已通过：345 项扩展回归、全部 9 个工程阶段、清理前后普通分块及检索输入的机制等价检查、真实实验库副本的迁移/中断恢复，以及实际中文回答的本地 BGE 追踪。中文样例只有一个，不构成多语言正确率评估；没有重跑历史 48 题并宣称新分数。父子和语义分块源码只保留在冻结实验与恢复快照中，LLM 对照、模型适配、版本链和索引回滚仍有使用场景，继续保留。

后续冻结查询计划和相同模型请求的 [v19 分块与预算验证](chunking-validation-v19.md) 得到固定分块 38/48、父子分块 37/48；放大全局预算、细化子块及修改分页修复提示均未提高父子方案正确数。下文保留 v17 原始结果，不能把两轮的差值直接解释为某个机制的因果贡献。

## 先回答是否值得重构

**建议先试点旧分块加本地 BGE；本轮父子分块参数不适合默认启用。** B1 的 48 题结果从基线 32/48 增加到 39/48，答题云端 token 减少 31.53%；但仍有 3 道原正确题回退，小样本及同模型 judge 不足以证明普遍正确率提升。增加父子分块后的 C 只有 33/48，固定组正确数下降，p95 超出预设门槛，因此没有整套切换默认配置。

| 48 题版本 | 正确数 | 答题云端 token | 相对 A | 答题 p50 / p95 |
| --- | ---: | ---: | ---: | ---: |
| A：冻结原实现 | 32/48（66.7%） | 526,775 | — | 20.38 / 100.48 秒 |
| B1：旧分块 + 受限 BGE 重排 | 39/48（81.3%） | 360,664 | −31.53% | 27.88 / 88.05 秒 |
| C：BGE + 父子分块 384/32 | 33/48（68.8%） | 425,676 | −19.19% | 29.95 / 162.68 秒 |

B1 token 含中断浪费，口径与限制见下文。价格未知，以上不是货币费用减少比例。BGE 能把重排计算移到本地；父子索引实现了完整问答关联、真实 token 限长及来源追溯；指纹拆分避免了仅改分块却重新调用云端抽取。机制收益可验证，答题效果仍受候选顺序、上下文预算、对象归属及模型判断影响。

| 维度 | 可能收益 | 代价与判定依据 |
| --- | --- | --- |
| 正确率 | 完整问答父块、句段重叠和邻近原文降低边界遗漏；BGE 改善候选阅读顺序 | 相关性分数不是事实可信度；旧信息仍可能排序靠前。用逐题净变化和回退分析判断 |
| 通用性 | `llm/bge/fusion` 后端、独立 tokenizer、CPU/MPS/CUDA、本地 tokenizer 文件；中文与英文来源均按原字符保存 | 配对模型仍有上下文上限；新 embedding 必须声明自己的 tokenizer 和模型 revision；未做多语言、多领域质量基准 |
| 云端成本 | BGE 不需要云端重排请求；分块迁移复用既有事实 | 分块会改变分页与证据长度，不能只减去原重排账单；统计实际输入和输出 token |
| 本地成本 | 模型惰性加载、进程内共享队列、按配对长度组批 | 增加权重、依赖、推理和排队时间；并发吞吐受单个设备限制；保留两代索引增加磁盘占用 |
| 维护与可审计性 | 写入、索引和读取指纹分离；迁移校验、事务切换、回滚、明确降级原因 | tokenizer 与模型身份需要管理；原库只有 embedding 别名，无法补造历史底层版本 |

BGE 官方说明支持此 multilingual cross-encoder 的 Transformers 用法；相关性评分不应解读为回答正确率。[官方模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3) 语义分块研究没有发现跨任务的稳定优势，因此本实现只对长文本选择性执行，默认关闭。[研究论文](https://aclanthology.org/2025.findings-naacl.114/)

## 已实现的范围

- 本地 BGE 后端固定模型与 tokenizer commit，支持惰性加载、共享推理队列、角色/日期/提问元数据及完整配对分窗。候选按窗口最大 logit 排序。运行失败明确退回融合排名；严格评测失败即终止该题，不能静默算作 BGE 成功。
- 父子索引以原始字符区间为真源。短轮次保留完整问答；长轮次按连续结构划分；子块使用真实 embedding tokenizer，把前缀及特殊 token 纳入上限，并带可追溯重叠。子块全文索引不会反复计入助手回答的提问前缀。
- 检索恢复父块并合并重叠来源，保留角色、日期及原文顺序；延续话题时有界扩展同会话先前轮次，仍经过安全视图和生命周期过滤。完整统计保留全体候选，BGE 只对受限数量打分，其余继续分页。
- 长文本语义边界使用本地句段向量，保持原文顺序；缓存按内容及声明的 embedding 身份隔离。结构方案和语义方案可独立开关。
- 事实抽取、索引、读取指纹分离。分块变化重建检索数据，同一向量空间的事实向量复用；声明的 embedding revision 改变时重算向量。正式写入对照若改变事实向量行为则重新建库。
- 新索引在来源指纹不变时事务切换，保留当前及上一代；校验字符覆盖、向量数量/维度、FTS 和父子对应。回滚只恢复检索数据，原文与事实版本不回退；来源或遗忘状态变化会拒绝旧代回滚，物理清理会删除历史索引载荷和语义缓存。
- `query_policy=on_risk` 与 `answer_review_policy=always/on_risk/off` 已提供。模型复核、操作语义、跨页处理和程序检查分别控制，按需策略尚需独立质量对照。

模块关系及迁移命令见 [架构文档](architecture.md#检索重构模块) 和 [README](../README.md#检索和分块重构)。新增机制回归在 `tests/test_rag_refactor.py`，实验入口在 `scripts/evaluate_retrieval_variant.py`，配对统计入口在 `scripts/compare_retrieval_variants.py`。

## 对照口径与限制

冻结旧源码 SHA-256 为 `4e8e5004e6105d0ce5965efb9d0f58f3b5519aa1b7ea06da03093cb660f5bf68`。A 使用冻结源码，后续版本复制同一事实库，只有 C 起重建索引。时钟、题目、预算、模型配置和 judge 保持一致，4 个问题并发。未复制旧答案、标签或追踪；全部答案完成之后，参考答案才进入 judge。逐库事实、原文、版本与生命周期身份在答题后再次核对，账本检查没有 `extract/resolve` 调用。

固定 34 题和此前的 14 题均已被使用过，是回归样本。它们不构成新的未见留出集，也不足以估计全量 500 题、中文质量或其他领域的准确率。没有默认重放 500 题。

本轮 A 复测为 **23/34 与 9/14**，此前记录的 **25/34 与 12/14** 没有复现。虽然配置别名、提示词及样本固定，云端底层模型 revision 没有公开，调用与 judge 也存在波动。账本保存的是配置模型名，旧客户端没有另存提供方响应的底层模型身份；因此这里不能声称锁定了未公开的实际权重。自动模型切换在质量实验中关闭。

B1 运行中本地 embedding 服务停止，20 题已完成、14 题连接失败。原可执行文件未找到，随后在实验目录恢复官方独立 Ollama `0.40.2`，未安装全局服务。恢复前后 `bge-m3` 摘要均为 `7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`；三个既有事实重算后，与冻结向量的归一化点积均接近 1。原服务运行时版本未记录，这仍是对照限制。续跑保留已完成答案与失败日志；中断前浪费的 **14 次查询、9,646 个云端 token** 纳入总用量并单列，失败等待不纳入成功答题延迟。

答题云端 token 指查询、云端重排、取证、生成和复核的实际输入加输出；排除本地 embedding 和评测 judge。它不是费用指标；当前价格未知，账本的数值 `0` 不代表免费。原始阶段用量、judge 开销另列于实验报告。延迟从读取答题开始计算，C 的迁移时间另计；p50/p95 使用现有报告的 `sorted[round(q*(n-1))]` 口径。它包含本地排队和云端等待，是该设备、该并发与样本下的观测。

资源门槛在 A 完成、B/C 运行之前写入 `resource-gates.json`：固定 34 题答题 p95 不超过 **130.59 秒**，进程生命周期峰值 RSS 不超过 **8 GiB**，报告的 MPS 当前分配不超过 **4 GiB**。RSS 不包含全部 GPU 内存，MPS 当前分配也不是设备总体瞬时峰值；这两个指标分别报告。

## 配对结果与回退审查

| 版本 | 固定 34 题 | 答题云端 token | 相对 A | 答题 p95 |
| --- | ---: | ---: | ---: | ---: |
| A：冻结原实现 | 23/34 | 415,834 | — | 100.48 秒 |
| B0：首轮本地 BGE | 23/34 | 272,399 | −34.49% | 198.98 秒 |
| B1：限制打分数量并按长度组批 | 27/34 | 280,094 | −32.64% | 88.05 秒 |
| C：父子分块 384/32 + BGE | 21/34 | 344,700 | −17.11% | 162.68 秒 |

B0 节省了云端 token，但没有提高净正确题数，延迟超出门槛。它曾对完整统计的全部候选执行本地重排，有题达到 198 个候选、253 个配对窗口；单设备共享队列进一步放大等待。后续 B1 限制打分候选数量、保留所有分页候选，并按窗口长度组批，重新评测。B0 的结果只作为修复原因，不能当作已验收默认方案。

B0 相比 A 有 6 题改善、6 题回退，涉及最新状态、完整统计、偏好和时间推理。一个拒答题的答案文本完全相同，judge 标签却不同；因此保留原始评分，同时明确 judge 波动，不能把所有变化归因于重排。模型分数也不能替代事实版本与证据核验。

B1 固定组有 7 题改善、3 题回退，净增加 4 题；其答题 token 含服务中断的 9,646 个浪费 token，正常完成路径为 270,448。三个回退逐题审查如下，标签没有重写：

| 回退类别 | 观测与证据 | 判断 |
| --- | --- | --- |
| 最新状态 | A 选入最新修正原文；B1 回答旧数值冲突，修正原文没有进入最终预算 | 候选阅读顺序和有限预算会损失最新修正；BGE 相关性不能代替状态裁决 |
| 具体日期 | A/B1 都选入相同原文，但 B1 回答只有年月，缺少具体日期 | 不只是召回问题；同来源的阅读、复核也会波动，父块恢复需要另测 |
| 限定条件拒答 | A 拒答获正确标签；B1 查询请求被提供方拒绝，启用现有启发式路径，最终也拒答但标签为错误 | 服务行为与 judge 波动混入此变化，不能单归因于 BGE；通用拒答没有说明所问限定条件不成立 |

逐题 ID、原答案、参考答案与追踪只保存在实验目录的 `comparison.json` 中，避免把已使用样本的内容写入会被实现与提示词扫描的仓库文档。

B1 的固定组 p95、RSS 与报告的 MPS 分配均满足预设门槛，全部 14 道完整检索题仍保留完整候选。进程生命周期峰值 RSS 约 759 MiB，MPS 当前分配约 2.13 GiB；重排排队 p95 为 15.53 秒，加载加推理 p95 为 12.20 秒。成功答题 p50 为 25.80 秒，A 为 17.61 秒：尾部延迟改善并不意味着简单问题也更快。

B1 原 14 题为 **12/14**，A 为 **9/14**，3 题改善且没有原正确题回退；答题 token 为 **80,570**，A 为 **110,941**。该组 p95 则从 **37.22 秒增加到 81.34 秒**，p50 为 **30.11 秒**，不能只看固定组的尾部改善。两组合计 A **32/48**、B1 **39/48**，答题 token **526,775 → 360,664**，其中 B1 含服务中断的额外查询用量。配对有 10 题改善、3 题回退，精确 McNemar 双侧检验 p≈0.092；此小样本结果不足以证明稳定的普遍正确率收益，且标签还有同模型 judge 和服务波动限制。

C 原 14 题为 **12/14**，答题 token **80,976**，p95 **79.53 秒**。与 A 合计只有 6 题改善、5 题回退，净增加 1 题；相比 B1 少正确 6 题，答题 token 反而增加 **18.03%**。固定组最新修正原文仍未进入最终预算；两个偏好题回退，其中一个发生查询服务降级；一个比较类拒答题变成未经完整时间支持的肯定答案。另一个拒答题与 A 答案完全相同却标签不同，保留该评分差异。单纯扩大父块没有解决状态与对象裁决，还改变了预算内可选来源。

固定 34 题的 C 索引有 **469 个父块、1,282 个子块**，A/B1 原有 **3,143 个子块**；当前向量载荷从 **22.33 MB 降到 14.71 MB**。保留两代索引额外占 **52.73 MB**，数据库分配空间从 A 的 **37.42 MB** 增到 C 的 **86.47 MB**（约 2.31 倍）。这组数字采用十进制 MB，不能用子块更少推断磁盘必然更省。WAL、模型权重和依赖环境另计。

## 本地预检与工程验证

官方实际模型已在 CPU 与 MPS 加载并完成真实推理。四条短候选的暖机测量中，CPU float32 为 0.39–0.48 秒，MPS float32 为 0.19–0.26 秒；MPS float16 为 0.16–0.22 秒。完整质量对照选择 MPS float32，避免同时改变精度；便于移植的配置默认设备仍为 CPU。首次下载并加载的观测约 234 秒，不能与缓存后的加载耗时混为一谈；微型工作负载也不能当作业务 p95。

实验的 Python 可选依赖环境约占 **888 MiB**，另需本地模型权重与 tokenizer 缓存；现有 Ollama `bge-m3` 权重约 **1.16 GB**。这些磁盘与设备开销不会出现在云端 token 账本里。

真实 BGE-M3 tokenizer 的中文、英文、列表、代码与相对日期样例已核验：原文片段逐字一致，区间并集完整，前缀和特殊 token 一并限长。机制测试覆盖遗忘、禁止读取、重叠、完整候选、失败降级、严格失败、向量空间变化、幂等迁移及回滚来源检查。

真实本地 embedding 的语义边界机制样例用时 **2.42 秒**，生成 7 个父块与 23 个子块，最大分别 **767/384 token**，来源并集完整。首次只计算 12 个不同句段向量，相同内容再次构建为 0 次新向量，仅改变一句后为 1 次新向量。此重复文本样例验证计数、缓存和边界行为，不代表真实问答准确率或一般索引吞吐；没有执行 D 的配对问答实验。

最终扩展环境 **342 项测试全部通过**；基础环境 342 项中有 2 项可选依赖测试跳过，其余通过。完整本地流程的测试、泄漏检查、写入覆盖、生命周期、规模、600 轮合成持续运行、扩展测试、向量加速与加速规模共 **9 个阶段通过**，保存于 `engineering-final/workflow.json`。其源码与重新冻结后的 C 实验一致，SHA-256 为 `d0a14e373cab82967b019c53af65dca05c1384cc9144635dd42fcae328ccbef0`。

C0 首次运行发现冷加载竞争，真实旧库副本回滚还发现新 FTS 补全缺口；两个问题已修复，并新增 3 项回归。实际磁盘演练已完成：子进程在事务中直接退出，未提交的向量/子块删除没有生效；旧索引回滚后向量逐字节一致、原文和事实来源指纹不变、旧子块 FTS 补全有效；再次恢复父子索引通过，遗忘后拒绝旧代回滚。结果保存在 `migration-drill/result.json`。工程测试和合成持续运行不等同于真实模型准确率。

## 配置决策

v17 评估期间，配置维持 `chunk_strategy=legacy`、`rerank_backend=llm` 及原查询与复核行为；语义分块关闭。实验使用独立配置和数据库副本。后续用户已授权将当前 `config.json` 切到 BGE，父子与语义分块不进入正式路径。

v17 已完成 A、B1、C 的两组配对验证，B0/C0 的失败或不完整记录保留；不完整 C0 不进入质量统计。B1 是可试点的成本方案，父子方案 C 没有通过质量和延迟门槛，因此 D/E/F 不继续作默认切换对照。后续清理移除了父子与语义分块运行能力；按需查询和按需复核仍需独立验收。没有用单题专用规则补指标，也没有自动回放全量 500 题。

如果后续继续优化 C，应先处理父块恢复与回答预算的关系、最新修正来源的优先级、完整聚合的分页开销，再用新的未见样本确认。跨语言和其他领域的通用性仍只有结构与机制证据。

## 交付与复现

`baseline/src` 保存 A，`frozen-sources/B1` 和 `frozen-sources/C` 保存与实验 SHA 完全一致的源码。`comparison.json` 是配对统计，`assessment.md` 保存逐题回退及原始答案；所有参考内容都留在实验目录。示例命令如下，换用对应 sample、事实库和新的输出目录即可复现：

```bash
python scripts/evaluate_retrieval_variant.py \
  --source runs/rag-refactor-v17/frozen-sources/C \
  --config runs/rag-refactor-v17/config-C.json \
  --sample runs/semantic-repair-v16/fixed34/sample.json \
  --stores runs/semantic-repair-v16/final4/fixed34/stores \
  --out runs/rag-refactor-v17/replay-C --workers 4 --reindex

```
