# V7 工作记忆与实体关系记忆构建计划

用户授权：先规划并构建，最后仅运行一轮 LongMemEval 小评测。生产改进不能根据评测问题或参考答案定制。

## 范围与架构

- 当前对话保留最近完整对话轮，同时执行独立的窗口预算；窗口淘汰前检查整理水位，失败保留待处理状态并明确报错，不静默丢失。
- 长期事实保留完整 value、限定条件、事件状态和来源。新增实体及关系结构，实体采用租户内稳定标识；只根据显式来源处理别名，歧义不强行合并。
- 关系索引保存实体端点、关系、有效时间、记录时间、来源和对应事实 ID。与事实一起事务提交，不复制成新的检索事实；Qdrant 继续作为存储。
- 首次回答前在事实检索之上进行受限的实体定位及 1～2 跳扩展，控制节点、边、候选及上下文预算，按事实 ID 去重。忘记或隐藏的事实不能经关系索引复活。
- 汇总检索需要处理覆盖状态；回答宿主在生成前完成有限事实补取，若预算仍不足则明确覆盖边界。回答阶段默认不读取历史原文。
- 本轮不新增图数据库，不自动生成经验规则。经验记忆保留为后续独立能力。

## 执行步骤

1. 记录现有配置和代码基线；机械冻结评测选题及写入、读取、判分输入，工作期间不查看其中的问题、历史或标签。
2. 实现实体／关系归一化、来源验证、索引持久化及旧数据兼容；扩展既有单次写入调用的 JSON 协议。
3. 实现事实关系召回、时间和生命周期约束、候选去重、预算与覆盖报告。
4. 实现完整轮工作窗口与整理水位衔接，统一 WebChat、CLI、服务和评测宿主的事实读取准备逻辑。
5. 用事先自写的实体关联、显式别名、同名歧义、状态变化、重复事件、遗忘隔离、预算及写入失败场景检查；运行适用的现有测试和泄漏检查。
6. 更新架构和使用文档；在不调用旧历史抽取服务的前提下兼容／更新现有关系索引，部署并检查本机服务。
7. 冻结最终源码、配置、提示词、评测脚本和输入哈希；只运行一次 write → read → judge，保留全部失败与中间结果，评测后不调参或补答。

## 唯一收尾评测

- 仅使用目录内 LongMemEval Oracle 文件；仍是 Oracle 历史条件，不把得分声称为全历史检索能力。
- `multi-session`、`temporal-reasoning` 各 8 道；`single-session-user`、`single-session-assistant`、`single-session-preference`、`knowledge-update` 各 4 道，共 32 道。
- 选题只使用题型、题号和拒答变体标识；预先固定种子，以哈希排序选择，排除可识别的既往使用题号。在有拒答候选的类别里固定纳入一题，其余名额正常抽样。
- 披露历史排除依据及可能无法识别的历史暴露；不根据标准答案、历史得分或内容挑选题目。
- 制样程序独立机械分离字段；write 不含题目及标签，read 不含标准答案，judge 在所有回答落盘后才能运行。
- 重新从原始历史建立隔离记忆；一次生成每题回答。统一传输重试沿用配置，失败保留且不选择性重答。
- 报告分题型及拒答子集、写入和回答完成率、事实／关系数量、候选扩展和覆盖情况、输入 token、耗时及可确定费用。原文上下文数量应为零。
- 这批题与上次 24 题不同，分数只能作小样本参考，不能作配对改进或 Mem0 优劣结论。不做消融和 500 题验收。
