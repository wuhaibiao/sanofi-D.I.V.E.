# 父子分块与预算验证（2026-10-10）

这轮没有找到提高父子方案正确率的改动。预算确实限制了父块还原，但直接放大全局预算使结果变差。现有默认方案和实际记忆库没有切换。

## 为什么父块经常超预算

冻结的 C 配置采用 `budget_mode=utf8`：回答预算按 UTF-8 **字节**计数，而分块使用真正的 BGE tokenizer。

| 设置 | 原值 | 实际单位与作用 |
| --- | ---: | --- |
| `parent_max_tokens` | 768 | BGE token，控制索引中的父块大小 |
| `episode_max_tokens` | 1800 | 字节，单条原文进入回答上下文的上限 |
| `context_budget_tokens` | 3500 | 字节，全部记忆共享，也用于取证分页与证据合成 |
| `answer_input_budget_tokens` | 8192 | 字节，规则、问题、记忆等完整消息的上限 |

实际单条上限为 `min(episode_max_tokens, 总预算 - 已选事实及对话的开销 - 1)`。普通问题优先给事实约 35% 的预算，需要完整召回的题约 60%；日期、标签、角色标题也占预算。同一命中对话还可能涉及多个父块，因此 768 个 BGE token 并不保证能装入 1800 字节。

48 题的检索记录有 350 次 `parent_exceeds_answer_budget`，包括后来未入选的候选尝试。长父块没有以 `[parent excerpt; …]` 形式进入最终记忆；放不下时程序退回查询相关摘录，并非截断父块直接交给回答模型。已选对话中有 18 次 `whole_short_turn`，这类短对话直接保留全文。

关闭父块还原、保留其余索引和重排行为后，**48/48 题的最终记忆字符串完全相同**。因此本轮下降不能解释为“大父块进入上下文后挤掉证据”。

## 同条件实验

48 题来自 v17 已使用的 fixed34 + used14，属于回归诊断，不是新测试集。沿用 B1/C 冻结代码和事实库，未覆盖当前工作区已有改动。

- 各方案的会话、原文、事实、来源和生命周期内容逐题相同；48/48 的身份校验通过。细子块方案只重建索引。
- 所有方案使用同一份 B1 查询计划，并校验问题文字及日期绑定，不重新调用查询规划、事实抽取或事实冲突消解。
- 回答、复核和评判使用 `gpt-6-luna`；embedding 使用本地 `bge-m3`；BGE 重排锁定模型版本、tokenizer、MPS 和 float32，严格模式禁止静默降级。
- 完全相同的模型请求共享成功响应。只有重新构造的全部重排输入窗口与已测记录逐字相同，且 tokenizer、模型版本和精度一致，才复用本地分数。改变输入就执行实际重排。
- 参考答案仅送入生成后的评判；没有重写评判标签。未使用历史回答来生成新答案。

| 方案 | 正确数 | 正确率 |
| --- | ---: | ---: |
| 固定分块原预算 | 38/48 | 79.17% |
| 父子分块原预算（子块 384 / 重叠 32） | 37/48 | 77.08% |
| 固定分块全局大预算 | 36/48 | 75.00% |
| 父子分块全局大预算 | 33/48 | 68.75% |
| 固定分块仅增单条上限 | 38/48 | 79.17% |
| 父子分块仅增单条上限 | 37/48 | 77.08% |
| 父子分块细子块（96 / 重叠 12） | 36/48 | 75.00% |
| 父子分块修改分页修复提示 | 37/48 | 77.08% |

“全局大预算”将单条上限 1800→4000、总记忆 3500→7000、完整输入 8192→16384，单位均为字节。固定分块同步扩大，避免把更多上下文的收益误算为父子分块的收益。

“仅增单条上限”只将 1800→4000，总记忆与分页仍为 3500、完整输入仍为 8192。这个补充实验在全局大预算退步后提出，属于探索性诊断，不是预先注册的新测试。

“修改分页修复提示”只在核验失败后要求模型返回原文行号范围，由程序复制原文；第一次取证请求、精确引用检查和两次尝试上限不变。

父子原预算相对固定原预算改善 2 题、退步 3 题，净少 1 题；精确 McNemar 检验 p=1。细子块相对父子原预算改善 2 题、退步 3 题；单条上限增大改善 2 题、退步 2 题。没有净提升，也不足以断言父子分块在总体上必然更差。

历史 v17 为 B1 39/48、C 33/48。新对照为 38/48、37/48，差距缩小；这表明历史差距不稳定，但不能据此计算“查询规划造成了几题下降”。两次实验之间仍有服务端模型状态、生成和评判变化。

## 为什么直接放大预算反而下降

父子大预算下，已选对话的全文保留决策从 18 次增加到 65 次；父块回退决策从 66 次减少到 51 次。放宽确实改变了上下文，但正确率从 37/48 降到 33/48，配对改善 3 题、退步 7 题。

这里存在预算耦合：`context_budget_tokens` 同时控制检索记忆、取证分页和证据合成。扩大后，父子方案的取证页数从 266 页减少到 123 页，每页内容变长。以下三题从正确变为核验失败：

| 回归情形 | 原预算 | 大预算 |
| --- | --- | --- |
| 累计状态 | 3/3 页，检查通过 | 1/1 页，累计状态被当作独立增量，计算检查失败 |
| 聚合证据 | 10/10 页，证据核验通过 | 5/5 页，没有选出相关且已核验的证据 |
| 分页引文 | 12/12 页，证据核验通过 | 3/6 页，原文引用不连续，停止处理 |

也有普通查找题退步，不能将全部损失归因于分页。更多上下文既可能补齐关系，也可能引入其他时间、状态或推荐范围；具体表现还受模型推理与评判影响。

仅增单条上限保留了分页大小，并减少部分回退，但净正确数不变。因此目前没有支持“把预算调大就能提高正确率”的证据。

## 新样本复查

在生成答案前，从此前所有 `hypotheses` 中未出现的题目按固定哈希顺序抽样；先选 18 题，再于查看答案前缩为每类 2 题，共 6 题。覆盖用户事实、多会话和时间推理三类，不含助手回忆和偏好类。

此前这些题对应的 oracle 数据库实际上为空，故仅用原始会话重新抽取一份共享事实库。查询计划也只生成一次，随后固定分块和父子分块各自检索同一批事实。48 题中没有改动优于原父子方案，因此按事先写入协议的平分规则，复查保留原父子方案，未用新样本选择改动。

| 方案 | 正确数 |
| --- | ---: |
| 固定分块原预算 | 3/6 |
| 父子分块原预算 | 2/6 |

这是小样本复查，不能推断总体正确率。实验 runner 的旧元数据将样本泛称为已使用回归集；这不适用于这 6 题。实际样本分类以 `fresh6-selection.json`、`protocol.json` 和独立复查目录为准，原冻结元数据保留以便审计。后续 runner 已加入 `--sample-status`，新样本实验可正确记录抽样时的状态。

## 保存的结果与验证

- 实验协议与全部配置：`runs/chunking-validation-v19/protocol.json`、`config-*.json`。
- 48 题配对结果：`runs/chunking-validation-v19/report48.json`；新样本结果：`report6.json`。
- 每题答案、原始评判和完整检索/核验记录：`answer/<variant>/`、`fresh-answer/<variant>/`。
- 事实身份与模型调用审计：`controls-audit.json`；子块重建结果：`fine-reindex.json`。
- 可复用实验工具：`scripts/evaluate_retrieval_variant.py`、`scripts/summarize_chunking_ablation.py`。
- 本轮实际执行的 runner 保存在 `runs/chunking-validation-v19/runner_frozen.py`，其 SHA-256 与 10 个完整回答实验的冻结记录全部一致；复现旧实验应使用该版本或新建输出目录。
- 冻结父子代码上，实验控制、取证核验、检索、父块索引及重排相关 **53 个测试通过**。这是定向验证，不代表当前工作区全部测试通过。

响应复用使各方案互相关联，也会改变实际调用数及耗时，故不能用这些耗时宣称部署性能提升。报告分别保存真实调用 token 与包括复用请求的 token 总量；服务方模型权重未公开，回答模型与评判模型相同，评判存在波动。

实际代码只补充了预算单位注释和实验工具；候选算法与预算配置保留在独立冻结目录中。本轮不推广大预算、细子块或修复提示为默认方案。后续若继续优化，需将检索/回答预算和取证分页预算分开，并在新的未使用样本上重新验证。
