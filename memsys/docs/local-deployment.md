# 本机部署

## Intel Mac 环境安装

在仓库的 `memsys/` 目录执行以下命令。项目使用独立虚拟环境；Intel Mac
使用 CPU，Apple Silicon 使用 MPS。Intel Mac 的 PyTorch 固定为最后支持
macOS x86_64 的 2.2.2，配套 Transformers 4.51.3 和 NumPy 1.x，安装时由
`pyproject.toml` 的平台条件自动选择。

```bash
uv python install 3.11
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e '.[strict,fast,rerank]'
source .venv/bin/activate
```

将模型配置写入本机 `config.json`，在 `.env` 中填写 `OPENCODE_API_KEY`。
这两个文件均被 Git 忽略；不要将密钥写入源码。首次准备需要下载固定版本的
BGE-M3、BGE reranker 权重，以及对应架构的原生 Qdrant 1.19.2 安装包。
两个 BGE 权重合计约 4.5 GB，另需预留依赖和运行内存。

准备好权重和数据库二进制后：

```bash
.venv/bin/python deploy/local.py prepare --qdrant-binary /path/to/qdrant
.venv/bin/python deploy/local.py start
.venv/bin/python deploy/local.py status
```

打开 <http://127.0.0.1:8848> 使用聊天页面。服务通过 macOS LaunchAgents
在登录时启动；`stop` 保留数据与启动项。`prepare` 不覆盖已有本机配置，
迁移旧的 MPS 配置到 Intel Mac 时需明确改为 CPU。

本机环境已安装时，也可双击 `memsys/启动本地服务.command`。它复用
`~/Library/Application Support/memsys/bin/qdrant` 中已准备的数据库程序，
首次启动在终端隐藏输入 OpenCode 密钥，再配置并启动三个本地服务。

后台服务使用 `~/Library/Application Support/memsys/.venv` 中独立安装的
包、该目录下的启动脚本与工作目录，避免 macOS 后台进程读取“下载”等受保护
目录时阻塞。安装后台环境时使用普通安装，不能使用 `-e`：

```bash
uv venv --python 3.11 "$HOME/Library/Application Support/memsys/.venv"
uv pip install --python "$HOME/Library/Application Support/memsys/.venv/bin/python" '.[strict,fast,rerank]'
```

启动入口会更新后台运行包。`prepare` 和 `start` 将已配置服务商的必要密钥
从项目 `.env` 同步到权限为 `600` 的 `provider-credentials.json`，后台进程
只读取这份私有副本；更换密钥后重启即可同步。源码改动后可再次双击启动入口
更新安装，再执行 `restart` 重启运行中的进程。

2026-10-14 重排增加单序列分词复用与分阶段计时。本机继续使用 MPS/float32、batch 4。缓存仅保存当前 tokenizer 下按完整文本内容散列的编码，最多 256 项、65536 tokens，不缓存相关性得分；修改事实内容后重新编码。查询只分词一次，最终配对通过原 tokenizer 的 postprocessor 构造，batch 直接对已有编码做 padding。长文本仍沿用原有完整覆盖的切窗规则，不减少候选或截断字段。

重排 trace 的 `timings_s` 区分 `load`、`tokenize_and_window`、`batch_prepare`、`model_and_readback` 和 `finalize`；`model_and_readback` 包含设备推理与同步读回，不是纯 GPU kernel 计时。保留原来的 `inference_and_load_s` 总口径，`tokenization` 记录本次编码工作量和缓存容量。三种自编中英文及长文本场景的本机对照见 [测速数据](../runs/rerank-optimization-20261014/comparison.json)。FP32 分数、窗口和排序一致，平均重排从 2.836 秒变为 2.713 秒；FP16 更快但出现 Top-5 集合变化，batch 8 未达到预设加速门槛，因此均未切为默认。此为模型已加载的本地重排测试，不是 LongMemEval 或完整答题耗时。

Embedding 端口兼容本项目的 OpenAI Embeddings 客户端，不是 Ollama 服务。BGE-M3 使用固定版本 `5617a9f61b028005a4858fdac845db406aefb181`，按官方默认 CLS pooling 和归一化产生稠密向量；模型输入超过 8192 tokens 时明确报错，不悄悄截断。[BGE-M3 官方说明](https://huggingface.co/BAAI/bge-m3)、[官方 pooling 默认值](https://github.com/FlagOpen/FlagEmbedding/blob/master/FlagEmbedding/inference/embedder/encoder_only/m3.py)

记忆采用整批单次抽取方式写入，完整事实字段相同才关联来源去重，没有独立裁决或答案复查。同批次的确定性结构解析保留助手列表的名称、原编号和短动作、表格的完整单元格，以及带明确标签和标题上下文的短数值字段。空抽取提示不触发自动重试；它表示语义覆盖待核对，不能据写入成功推断内容完整。Embedding 的原文向量分段与整批 LLM 抽取是不同步骤。

在项目根目录执行：

```bash
.venv/bin/python deploy/local.py start
.venv/bin/python deploy/local.py status
.venv/bin/python deploy/local.py restart
.venv/bin/python deploy/local.py stop
```

`stop` 停止本次运行但保留数据和登录启动项；下次登录仍会启动。`restart` 用于修改本地配置、密钥或代码后重启服务。三个登录启动项为 `com.memsys.qdrant`、`com.memsys.embedding`、`com.memsys.memory`，均只监听回环地址。

本地部署数据位于 `~/Library/Application Support/memsys/`：

- `config.json`：本机模型、检索及 Qdrant 配置。
- `runtime.json`：私有部署元数据和本机访问令牌，权限为 600。
- `qdrant/storage/` 与 `qdrant/snapshots/`：本机数据库与快照。
- `memory/`：记忆服务轨迹；`logs/`：各服务日志。

本机使用独立的 `local` 命名空间，未从云端复制历史数据。新生成的本机配置不会覆盖原项目配置；抽取模型的密钥在进程启动时读取项目 `.env`。模型文件准备后，运行服务使用本机缓存，不在第一次请求时联网下载权重。

## 网页使用

打开 `http://127.0.0.1:8848`，本机部署会自动连接 `local` 账户。浏览器仅使用 HttpOnly、SameSite 会话 Cookie；不会收到模型或数据库密钥。自动连接只在明确启用的回环监听部署中生效，网页接口检查 Host 与 Origin。现有 `/memsys/*` 接口仍需要原来的用户或管理令牌，网页 Cookie 不授予管理 API 权限。

- 在输入框发送消息，Enter 发送，Shift + Enter 换行。
- 左侧可搜索、重命名、归档和继续已有对话；历史保存在 Qdrant。
- 新建对话或切换到侧栏另一段已有对话，会结束离开的会话并后台整理记忆；重新打开历史对话时可以继续聊天。同一对话刷新不触发关闭。关闭请求表示任务已排队，抽取和索引完成后才可从长期记忆中检索。
- 默认 `recall_mode="facts"` 只用已整理的事实作为长期记忆，不附检索来源原文，也不补入其他会话及当前短期窗口外尚未整理的原文。后台未完成或失败时，相关内容需等待事实整理后才能用于跨会话回答。当前对话保留受预算限制的最近 12 条消息。旧的原文补充只在显式诊断模式 `facts_and_sources` 中启用；下文 2026-10-13 的原文补充验证是历史行为，不代表当前默认流程。
- 侧栏显示“原文已保存 · 待整理”“等待整理”“正在整理”“整理已完成”或“整理失败”。后台任务进行中会更新显示；失败时可点击旁边的重试按钮。整理完成表示本段处理已结束，不能据此宣称所有问题都能正确回答。
- 每次回答都会自动检索相关记忆，没有关闭选项；检索失败时明确返回错误，不跳过记忆继续生成。归档对话不会删除长期记忆。
- 回复支持 Markdown、代码块和复制；等待时显示状态，失败后可以重试。
- 左下角账户按钮可查看当前账户与回答模型；页面采用浅色界面。

网页作为宿主 Agent 生成最终答案，记忆核心只负责检索与存储。未配置独立 chat 角色时，网页复用既有 memory 角色作为回答模型；每次发送正常调用一次最终生成，没有额外的标题生成或答案复查。目前等待状态通过 SSE 返回，答案完成后整段展示，尚未实现模型 token 流式输出。
